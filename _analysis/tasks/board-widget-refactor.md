# 开发任务：重构自定义 Launcher 桌面阅读组件，实现极简杂志风格的多书籍轮播

## 一、项目背景

本项目是我自行开发的 Android 桌面启动器（Launcher）。

其中已经实现一个桌面阅读组件，目前能够：

- 展示一本用户选择的书籍。
- 使用现有备选书籍选择机制。
- 获取书籍封面、书名、阅读进度和阅读时长。
- 通过“打开”按钮进入对应书籍。

现在需要重构这个桌面阅读组件，将原有的单书展示模式升级为**多书籍层叠封面轮播模式**。

注意：

1. 这不是 Android 原生 AppWidget，不使用 AppWidgetProvider 或 RemoteViews。
2. 这是 Launcher 内部自行开发的桌面组件。
3. 可以利用当前项目的 UI 技术栈实现自定义布局、水平触摸手势、动画和数据更新。
4. 不需要重新实现书籍数据获取、阅读器启动或备选书籍管理功能。
5. 不要擅自改变项目架构。

本任务不提供设计图片，因此以下文字就是完整的 UI 设计规范。请严格按照文字描述实现，不要自行套用常规 Android 书架模板。

# 二、总体视觉目标

实现一个**黑白极简、文学杂志式排版、具有层叠封面视觉效果的桌面阅读组件**。

它不是常规的书籍列表，也不是带背景色和阴影的 Material 卡片。

整个组件应当像一张精心排版的极简文学海报。

视觉关键词：

- 黑白配色
- 大面积纯白背景
- 文学杂志排版
- 极简主义
- 衬线字体
- 层叠书籍封面
- 居中视觉焦点
- 大量留白
- 扁平化设计
- 克制的过渡动画

核心设计结构：


注意：上面的字符示意仅用于说明结构，实际布局应采用封面重叠而不是这些矩形并排连接。

其中最重要的是：

**中央书籍最大、最靠前，两侧书籍逐级缩小并向后叠放，呈现横向扇形展开的平面封面组合。**

不要加入透视旋转或明显的 3D 效果。

# 三、整体布局与比例

设计基准为横向矩形桌面组件。

以组件可用宽度 W、高度 H 为参考。

建议使用以下布局比例作为初始值，之后根据真实设备和现有桌面网格适配：

| 区域             | 推荐位置     |
| ---------------- | ------------ |
| 顶部时间及笔记区 | H 的 5%–22%  |
| 中部封面轮播区   | H 的 32%–78% |
| 当前书名         | H 的 79%–85% |
| 阅读进度条       | H 的 87%–89% |
| 底部阅读信息     | H 的 91%–97% |

这些比例是设计参考，不要求机械使用绝对定位。应优先保证各区域不重叠和组件尺寸变化时的稳定性。

### 整体背景

- 默认纯白 `#FFFFFF`。
- 主文字黑色 `#111111`。
- 次要文字深灰色 `#555555`。
- 阅读进度条底色 `#DADADA`。
- 不添加额外背景卡片。
- 不添加大圆角容器。
- 不添加渐变。
- 不添加厚重阴影。
- 不添加复杂边框。

最终效果要像一张独立排版的纸面，而不是由多个 UI 卡片拼起来的界面。

# 四、顶部左侧：大号时间与日期

顶部左侧设置实时时间和日期。

## 时间

示例：

22:24

视觉要求：

- 采用 24 小时制。
- 时间为整个组件中字号最大的文字之一。
- 使用粗体衬线字体，优先使用现有可用字体。
- 字重 600–700。
- 颜色为纯黑或接近纯黑。
- 数字之间保持自然紧凑间距。
- 时间整体左对齐。

以组件宽度约 1080 设计单位的示例布局为参考，时间字号可以从 85–100 设计单位开始调整。

实际实现必须依据布局尺寸、density 和字体缩放进行适配，不可直接将示例设计单位作为所有设备上的固定 px。

## 日期

时间正下方显示日期。

例如：

星期三，10月7日

要求：

- 使用真实系统日期。
- 日期和时间左对齐。
- 日期字号约为时间字号的 22%–28%。
- 字重正常。
- 与时间之间留少量空隙。
- 显示格式遵循中文日期习惯。

时间和日期更新应使用项目现有的时钟或生命周期机制，不要增加高频后台轮询。

# 五、顶部右侧：当前书籍划线笔记

在顶部右半部分展示当前书籍的一条划线笔记。

例如：

“就连自己生存于这个世界的状态，
都像是不牢靠的幻觉。”

— 眼，村上春树

### 排版要求

- 笔记区域位于顶部右侧。
- 与左侧时间共同组成顶部双栏布局。
- 占用顶部宽度约 48%–55%。
- 正文使用中文衬线或宋体风格。
- 字体黑色。
- 正文居中或偏右对齐。
- 字体大小约为日期字号的 90%–110%。
- 支持自然换行。
- 最多展示 2–3 行正文。
- 超出时使用省略或截断处理。
- 笔记来源放在正文下方。
- 来源信息靠右对齐。
- 来源字体略小于正文。

### 数据要求

必须获取**当前中央选中书籍对应的划线笔记**。

优先复用当前项目的划线笔记数据库、接口和已有筛选逻辑。

如果同一本书有多条划线笔记：

- 优先使用项目现有选择规则。
- 如果没有明确规则，默认显示最近一条有效划线笔记。
- 不要自行生成或伪造文字。

如果当前书籍没有任何划线笔记：

- 不显示笔记正文。
- 不显示笔记来源。
- 不显示“暂无笔记”。
- 不显示占位边框或提示。
- 保留时间与日期。
- 不因为没有笔记而影响中部封面布局。

# 六、中部核心：层叠书籍封面轮播

这是本次 UI 重构最核心的部分，需要重点实现。

## 1. 视觉构成

默认最多展示 5 本书籍的封面：

- 中央：当前书籍。
- 左侧第一层：上一本书。
- 左侧第二层：上上本书。
- 右侧第一层：下一本书。
- 右侧第二层：下下本书。

超出可视范围的书籍不需要同时渲染。

### 层叠关系

中央封面永远处于最前方，拥有最高的绘制层级。

左右封面逐级向后。

绘制层级：

1. 中央封面：最高。
2. 左右第一层封面：中等。
3. 左右第二层封面：最低。

被遮挡的封面不需要完整显示。

### 具体尺寸比例

以中央封面宽度 C 为基准：

| 封面位置   | 宽度比例 | 高度比例 |
| ---------- | -------- | -------- |
| 中央       | 100%     | 100%     |
| 左右第一层 | 82%–88%  | 88%–92%  |
| 左右第二层 | 72%–80%  | 78%–85%  |

所有封面尽量保持真实书封比例。

如果真实封面比例不同，应选择不明显变形的裁切或适配策略。

### 中央封面

- 水平居中。
- 比其他封面更大。
- 顶部略高于两侧封面。
- 底部也略低于两侧封面。
- 完整展示封面。
- 不使用大圆角。
- 不使用明显阴影。
- 保持视觉上具有绝对的焦点地位。

### 左右第一层封面

- 分别位于中央封面的左右后方。
- 与中央封面发生明显水平重叠。
- 只露出大约 30%–45% 的自身宽度。
- 高度略低于中央封面。
- 垂直中心与中央封面大致对齐。
- 不能与中央封面处于相同的绘制层级。

### 左右第二层封面

- 位于左右第一层封面的更后方。
- 只露出较窄的封面边缘。
- 尺寸更小。
- 垂直居中。
- 视觉上形成由中央向两侧递减的层次。

### 视觉重点

所有封面应当像一组被横向展开的实体书封面：

- 前后遮挡关系清楚。
- 位置相对对称。
- 不应出现大面积空隙。
- 不采用统一间隔排列。
- 不采用明显的 Y 轴 3D 旋转。
- 不要给封面加白色卡片容器。
- 不需要封面下方的独立作者信息。

封面图片本身保持原始色彩，不需要强制转成黑白。黑白极简主要体现在整体布局和文字设计上。

# 七、左右滑动切换书籍

将原来的单本书展示升级为可交互的多书籍轮播。

## 1. 手势交互

在封面区域内：

- 手指向左滑动：切换至下一本书。
- 手指向右滑动：切换至上一本书。
- 一次标准滑动切换一本书。
- 滑动距离不够时恢复当前位置。
- 垂直移动不应误触发水平切换。
- 在 Launcher 允许的情况下，与桌面页面左右滑动进行正确的手势冲突处理。

特别注意：

**不能因为书籍轮播的水平手势而破坏整个 Launcher 原有的桌面翻页手势。**

请检查当前 Launcher 的触摸事件分发机制，明确何时由阅读组件消费水平手势，何时交给桌面父容器。

## 2. 切换动画

建议采用轻量级位置、缩放和层级过渡。

例如从 A 切换到 B：

1. 中央 A 向左侧移动。
2. 右侧 B 平移到中央。
3. B 逐渐放大至中央尺寸。
4. A 缩小为左侧封面。
5. 其他封面按照新索引调整位置和层级。

参考动画时长：

200–300ms。

建议采用 ease-out 风格的缓动。

要求：

- 动画平滑。
- 不使用复杂 3D 特效。
- 不使用弹跳或过度回弹。
- 不使用高成本模糊动画。
- 快速连续滑动不应造成索引错误或视觉错乱。

如果项目使用 Android 原生 View、Compose 或 WebView，请选择当前技术栈最适合的轻量实现，不引入另一套 UI 技术框架。

## 3. 点击两侧封面

除了滑动外：

- 点击左侧可见封面可以切换到对应书籍。
- 点击右侧可见封面可以切换到对应书籍。
- 点击中央封面可根据项目原有行为决定是否打开阅读器。
- 点击空白区域不应导致误切换。

## 4. 边界行为

默认采用有限列表模式：

- 第一本文书不能继续向右切换到不存在的前一本。
- 最后一本不能继续向左切换到不存在的下一本。
- 不实现循环轮播，除非当前项目已有明确的循环模式。
- 只有一本备选书籍时只显示中央封面。
- 有两本或三本时只显示实际存在的邻近封面。
- 不得通过复制书籍制造虚假的封面数量。

# 八、备选书籍来源与状态保持

这部分必须严格保留原有逻辑。

当前桌面阅读组件已经存在手动选择备选书籍的功能。

新轮播中的所有书籍必须来自这个原有机制。

要求：

1. 继续使用当前备选书籍列表。
2. 保留原有备选书籍的顺序。
3. 不默认读取全部书架。
4. 不改变备选书籍的增删、选择和保存方式。
5. 不修改原有书籍 ID 及数据结构。
6. 轮播当前索引应当与有效书籍 ID 关联。
7. 组件重新加载时优先恢复上次展示的书籍。
8. 如果上次展示书籍已不在备选列表中，选择一个有效书籍作为回退。
9. 备选书籍列表发生变化时正确刷新轮播。

多个桌面阅读组件实例存在时，优先遵循项目原有的状态隔离设计，不要让不同实例相互覆盖选中状态。

# 九、中部下方：当前书籍名称

封面轮播下方显示当前书籍的书名。

例如：

1Q84

要求：

- 水平居中。
- 黑色。
- 字号明显大于底部阅读信息。
- 采用与整体设计协调的衬线或具有文学气质的字体。
- 字重中等或偏粗。
- 书名与封面之间保留适当间距。
- 不显示作者名。
- 不显示分类、页数或其他元数据。
- 超长书名最多显示两行或按可用宽度截断。

# 十、底部阅读进度与操作

底部采用两层极简排版。

第一层是横向阅读进度条。

第二层是阅读百分比、阅读时长及打开按钮。

## 1. 阅读进度条

位于书名下方，水平居中。

样式：

- 宽度约为组件总宽度的 22%–30%。
- 高度较细。
- 浅灰色轨道。
- 黑色或深灰色已读部分。
- 接近直角，不使用明显的圆角胶囊。
- 不使用渐变和发光效果。

进度值必须来自当前选中书籍的真实阅读状态。

## 2. 阅读百分比

进度条下方偏左位置显示：

已读 1%

要求：

- 中文“已读”加整数百分比。
- 使用实际阅读进度。
- 文字黑色。
- 与阅读时长保持统一字号。
- 不显示页数。

## 3. 阅读时长

阅读百分比右侧显示：

9h 3m

要求：

- 继续使用项目当前的累计阅读时长数据。
- 格式为 Xh Ym，具体可根据原有格式适配。
- 数据随当前书籍切换而更新。
- 不重复计算或修改阅读历史。

## 4. 打开按钮

位于阅读时长右侧。

样式：

- 简单黑色矩形细边框。
- 白色背景。
- 黑色文字“打开”。
- 不使用圆形悬浮按钮。
- 不使用彩色填充。
- 按钮宽度紧凑，高度适中。

行为：

**点击打开按钮，必须打开当前中央正在展示的书籍。**

原有阅读器启动、书籍 ID 传递和阅读进度恢复逻辑必须保持正常。

## 5. 底部信息排列

整体在组件中水平居中：

已读 1%　·　9h 3m　·　[打开]

其中两个分隔点仅是排版元素，不需要交互。

所有内容应在视觉上形成统一的水平信息带。

# 十一、切换书籍时的数据同步

当中央书籍变化时，必须同步更新以下内容：

| UI 元素    | 数据                   |
| ---------- | ---------------------- |
| 中央封面   | 当前书籍封面           |
| 左右封面   | 当前索引对应的相邻书籍 |
| 当前书名   | 当前书籍名称           |
| 右上角笔记 | 当前书籍的划线笔记     |
| 阅读进度条 | 当前书籍阅读进度       |
| 阅读百分比 | 当前书籍已读百分比     |
| 阅读时长   | 当前书籍累计阅读时长   |
| 打开按钮   | 当前书籍 ID            |

建议内部维护统一的 selectedBookId 或 selectedBookIndex 作为展示状态，并以选中的书籍 ID 作为最终数据关联依据。

不要为封面、笔记、进度条分别维护互不关联的选中索引。

必须避免：

- 封面已切换，书名还未更新。
- 笔记仍然对应上一本文书。
- 阅读进度对应错误书籍。
- 快速切换后打开按钮打开错误书籍。
- 异步读取笔记时，旧请求覆盖新书籍信息。

时间日期不随书籍切换。

# 十二、Launcher 特有的交互与生命周期要求

因为这是自定义 Launcher 内部组件，而不是系统 AppWidget，请重点检查：

### 1. 桌面手势冲突

- 阅读组件水平滑动与桌面翻页如何协调。
- 滑动起点位于封面区域时才触发书籍切换。
- 滑动起点位于组件其他位置时尽量维持桌面原有行为。
- 不拦截整个桌面的水平触摸事件。
- 不影响桌面长按编辑、拖动小组件或桌面翻页功能。

### 2. 组件状态

- Launcher 页面切换后，当前书籍状态保持合理。
- Launcher 进程重建后可以恢复。
- 书籍列表更新后正确校验当前索引。
- 书籍切换结束后保持与显示内容一致的选中状态。

### 3. 性能

目标设备约 2GB RAM。

要求：

- 同时只渲染必要的可见封面。
- 不要一次性加载所有备选书籍的高清大图。
- 优先使用缩略图或尺寸适配的解码。
- 复用现有图片加载与缓存机制。
- 避免无意义的持续动画。
- 对于不可见的桌面页面减少不必要刷新。
- 避免时间显示触发整个封面区域重复渲染。
- 不引入大型第三方轮播组件，除非现有技术栈确有必要。

### 4. 技术兼容性

请先检查项目采用的是：

- Android View
- Jetpack Compose
- WebView + HTML/CSS/JavaScript
- 或其他自定义渲染方案

然后使用当前项目技术栈完成。

# 十五、最终验收标准

1. 整体为白底黑字的极简文学杂志风格。
2. 左上角是大号时间，下方是日期。
3. 右上角显示当前书籍的划线笔记，没有则完全隐藏。
4. 中间为最多五本书籍的层叠封面，中央最大、两侧依次缩小。
5. 封面可以通过左右滑动切换。
6. 相邻封面可以点击切换。
7. 封面切换具有轻量、流畅的过渡动画。
8. 中央封面下方显示大号书名。
9. 下方为简洁的阅读进度条。
10. 最底部显示已读百分比、累计阅读时长和打开按钮。
11. 打开按钮能够打开当前书籍。
12. 所有阅读信息与当前封面同步。
13. 轮播候选书籍完全沿用原有备选书籍机制。
14. 不破坏 Launcher 原有桌面翻页、拖动和编辑交互。
15. 在目标低内存 Android 设备上运行稳定。
