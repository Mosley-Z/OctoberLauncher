## 规则改写

### 改写前

`app/proguard-rules.pro` 共 2 行，唯一规则为 `-keep class com.shuiyu.octoberrain.** { *; }`。该规则使全部 594 个自有类连同全部成员进入保留集合，R8 的类名重命名、成员裁剪与资源标识压缩均不生效，release 与 debug 的代码结构一致，混淆形同未启用，同时放大了安装包体积与方法数。

### 改写后

`app/proguard-rules.pro` 共 50 行，其中注释 25 行、规则 17 条，按三类运行期依赖组织，每条保留规则注明依赖位置与失效后果：

| 保留类别 | 规则形式 | 保留原因 |
| --- | --- | --- |
| 五个模块实现类 | `-keep class ...feature.{home,widgets,tray,settings,content}.*Module { public <init>(); }` | `OctoberRainApp.installModules` 在 `OctoberRainApp.kt:87-91` 以固定类名字符串调用 `Class.forName`，`OctoberRainApp.kt:96` 取无参构造器实例化；类名或构造器重命名即导致启动阶段模块装载失败 |
| 模块内部类名 | `-keepnames class ...*Module$*` | 仅保留类名用于日志与异常堆栈对照，成员仍参与混淆与裁剪 |
| 配置序列化 | `-keepclassmembers *** Companion`、`-keepclasseswithmembers ... KSerializer serializer(...)`、`-keep,includedescriptorclasses ...**$$serializer { *; }` | `LauncherConfig` 及子配置由 kotlinx.serialization 读写 JSON，编解码依赖生成序列化器与 Companion 入口；裁剪后配置读写回退为空配置 |
| 组件实现 | `-keep class * implements com.shuiyu.octoberrain.core.widget.WidgetProvider { *; }` 与 `-keep class * implements ...WidgetView { *; }` | 组件由 `WidgetCatalog` 工厂注册并以接口绘制，组件标识同时写入配置，实现类保留以避免登记表与绘制路径在优化下被切断 |

保留范围由“全部自有类”收窄为 63 个类。文件行数由 2 行增至 50 行，原因是每类保留理由需要注释说明；覆盖类数量由 594 降至 63，混淆实际生效，判定指标以覆盖类数量为准。

### 签名配置

`app/build.gradle.kts:26` 在 `release` 构建类型内指定 `signingConfig = signingConfigs.getByName("debug")`，沿用计划 D7 的约定：V1.0 阶段以调试签名验证发布产物可安装，正式发布前替换为独立签名与密钥。该改动不触碰签名密钥文件，调试证书由 Android 构建插件在本机与 CI 环境自动生成。

以 dex 反汇编逐项核对模块类是否真实存在于发布产物：

## 遗留问题

1. 发布产物使用调试证书，仅用于 V1.0 内部验证；正式发布前需按 D7 替换独立签名与密钥，替换涉及密钥文件，需单独授权后执行。
2. 本次验证为静态验证：构建成功、签名有效、类名与构造器存在、dex 与映射一致。设备级安装与启动冒烟未执行，当前环境无可用设备或模拟器；真机验证列入后续版本门禁。
3. 序列化规则采用 kotlinx.serialization 官方推荐形式，未在真机验证配置读写往返；若后续调整模型结构，需同步复核 `$$serializer` 保留规则。
4. `WidgetView` 接口本身被重命名，接口调用不依赖名称，静态检查未发现风险；若后续出现通过类名字符串定位视图实现的逻辑，需要追加保留规则。
