## 二、使用统计权限的版本分支

### 2.1 原实现与缺陷

三处调用点均直接使用 `AppOpsManager#unsafeCheckOpNoThrow`。该方法的可用性标注为 API 29，工程 `minSdk` 为 26，Android 8.0 至 9.0 设备调用时抛 `NoSuchMethodError` 或等价异常，被 `runCatching` 或 `try/catch` 吞掉后返回 false，表现为权限始终显示未授予。

`core/device/src/main/java/com/shuiyu/octoberrain/core/device/PermissionCenter.kt` 修改前：

```kotlin
    /** 是否具备使用情况访问权限。 */
    fun hasUsageAccess(): Boolean {
        return try {
            val appOps = context.getSystemService(android.app.AppOpsManager::class.java)
            val mode = appOps.unsafeCheckOpNoThrow(
                android.app.AppOpsManager.OPSTR_GET_USAGE_STATS,
                android.os.Process.myUid(),
                context.packageName,
            )
            mode == android.app.AppOpsManager.MODE_ALLOWED
        } catch (e: Exception) {
            false
        }
    }
```

`app/src/main/java/com/shuiyu/octoberrain/OnboardingScreen.kt` 修改前（`:178-186`）：

```kotlin
    /** 是否已授予使用情况访问权限。 */
    private fun hasUsage(): Boolean = runCatching {
        val appOps = context.getSystemService(android.app.AppOpsManager::class.java)

            android.app.AppOpsManager.OPSTR_GET_USAGE_STATS,
            android.os.Process.myUid(),
            context.packageName,
        )
        mode == android.app.AppOpsManager.MODE_ALLOWED
    }.getOrDefault(false)
```

`feature/content/src/main/java/com/shuiyu/octoberrain/feature/content/RecentsRepository.kt` 修改前（`:198-216`）已含版本分支，但与上述两处重复维护，且未复用。

### 2.2 新增判定函数

新增 `core/device/src/main/java/com/shuiyu/octoberrain/core/device/UsageAccessChecker.kt`（42 行）：

```kotlin
object UsageAccessChecker {
    private const val OP = AppOpsManager.OPSTR_GET_USAGE_STATS

    fun isGranted(context: Context): Boolean {
        val appContext = context.applicationContext
        val appOps = appContext.getSystemService(AppOpsManager::class.java) ?: return false
        return runCatching {
            val mode =
                if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q) {
                    appOps.unsafeCheckOpNoThrow(OP, Process.myUid(), appContext.packageName)
                } else {
                    legacyMode(appOps, appContext.packageName)
                }
            mode == AppOpsManager.MODE_ALLOWED
        }.getOrDefault(false)
    }

    /** Android 8 与 9 的分支，调用已废弃的 checkOpNoThrow，结果语义与新方法一致。 */
    @Suppress("DEPRECATION")
    private fun legacyMode(
        appOps: AppOpsManager,
        packageName: String,
    ): Int = appOps.checkOpNoThrow(OP, Process.myUid(), packageName)
}
```

系统版本分支、应用上下文获取与异常降级集中在单处，调用点只关心布尔结果。

## 六、真机检查

设备 SA4B03CN2608081096X，Android 11（API 30），调试包安装后检查权限状态与系统设置是否一致。

### 6.1 检查方法

系统侧的授权状态用 AppOps 读写，界面侧用截图与界面层级核对：

```
adb shell appops get com.shuiyu.octoberrain GET_USAGE_STATS
adb shell appops set com.shuiyu.octoberrain GET_USAGE_STATS allow
```

应用以自绘 View 呈现界面，`uiautomator dump` 只能取到少量节点，导航按截图坐标完成。路径为桌面第 2 页「设置」→ 设置首页「桌面偏好」→「权限与授权」。

### 6.2 一致性结果

| 系统 AppOps 状态 | 权限页显示 | 已授权计数 |
| --- | --- | --- |
| `No operations. Default mode: default`（未授权） | 「使用情况访问 未授权」 | 3 / 7 |
| `GET_USAGE_STATS: allow` | 「使用情况访问 已授权」 | 4 / 7 |

授权状态切换后退出并重新进入该页，显示与系统一致，说明 `PermissionCenter` 经 `UsageAccessChecker` 得到的结论正确。

### 6.3 引导页

删除应用配置后重启进入引导页，三步依次为「十雨桌面」欢迎页、「选择桌面形态」、「授予必要权限」。第三步的「使用情况访问」显示「已授权」，与当时 AppOps 的 `allow` 状态一致。

检查结束已恢复：删除新生成的配置，把备份的 `octoberrain_config.xml`（3843 字节）改回原名，删除临时副本，重启应用并删除设备端临时目录 `/sdcard/t17`。

## 七、遗留事项

- Android 8.0 至 9.0 设备未实测。当前可用的真机为 API 30，`CheckOpNoThrow` 旧分支只有代码路径覆盖，缺少 `Build.VERSION.SDK_INT < Q` 的实际运行验证。后续可借用 Android 9 设备或模拟器补测，重点确认 `checkOpNoThrow` 返回 `MODE_ALLOWED` 与权限页显示一致。
- Android Lint 存量 82 条中仍有错误级别条目（`app` 2 条、`core:data` 5 条），均位于基线内、本次未处理。基线机制保证新增问题会失败，存量问题按模块逐步清理。
- `docs/08-engineering-conventions.md` 的 Lint 条目数已由 84 更新为 82，detekt 条目数 237 未变。
