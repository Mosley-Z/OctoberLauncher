# 0.9.8 壁纸替换与量化复验

## 一、结论

桌面壁纸的量化链路在 P5 已接入，无需补写；本次复核确认桌面壁纸与锁屏壁纸均按各自配置档位经过 `WallpaperQuantize`。复核中发现桌面与锁屏壁纸替换均为「先删除旧文件、再复制新文件」，复制或校验失败时配置仍指向已删除的旧路径，壁纸丢失。已将替换流程改为「写入新文件并校验、更新配置、删除旧文件」三段顺序，任一环节失败均保留旧文件。

## 二、现状核对

桌面壁纸：`app/.../WallpaperView.kt:54` 监听配置时读取 `wallpaperPath` 与 `wallpaperQuantize`，`:100` 调用 `AppServices.appearance.loadWallpaper(width, height, quantize)`。`AppearanceRepositoryImpl.loadWallpaper`（:64-71）转调 `loadWallpaperFile`，再经 `decodeWallpaper` 与 `renderWallpaper`（:297-332）完成采样解码、居中裁剪、白底填充与 `WallpaperQuantize.apply`。

锁屏壁纸：`LockWallpaperView` 以 `lockWallpaperQuantize` 调用 `loadLockWallpaper`（`AppearanceRepositoryImpl.kt:93-100`），同样经过 `loadWallpaperFile` 与 `renderWallpaper`。两项壁纸的路径字段与前缀（`wallpaper`、`lock`）分离，未发现串用。

## 三、修复点

新增 `core/data/.../WallpaperSwap.kt`：`internal class WallpaperSwap(directory, openSource, isValidImage, updateConfig)`。`execute(prefix, timestamp, previousPath)` 先写入新文件并校验，校验失败清理新文件并返回 false；随后调用配置更新函数，配置未确认更新时删除新文件并返回 false；两步均成功后才删除旧路径文件。文件名保持 `<prefix>_<时间戳>.png`，同名冲突追加 `_2` 至 `_999`。旧路径为空、文件不存在或与新文件同路径时跳过删除。

`AppearanceRepositoryImpl` 的 `setWallpaper` 与 `setLockWallpaper` 改用该事务：`desktopSwap` 与 `lockSwap` 分别注入配置更新函数，更新后读取 `config.state.value.appearance` 校验路径写入结果。删除原 `copyWallpaperFile` 与 `java.io.FileOutputStream` 导入。清除路径保持原逻辑：删除当前文件后把路径置空或置为默认值。

## 六、真机验证

设备为 S4 480×800、219 dpi、Android 11（API 30）。截图为 `_analysis/team/shots/dev-config-0.9.8-*.png`。

替换顺序：初次设置壁纸生成 `wallpaper_1792437519785.png`（260,619 字节）并写入 `wallpaperPath`；再次选择另一张图片后生成 `wallpaper_1792437557875.png`（15,391 字节），旧文件 `wallpaper_1792437519785.png` 被删除，配置中的路径同步更新，目录内只剩新文件与一张历史遗留文件。

量化：桌面量化设为二级灰（`wallpaperQuantize=1`）后桌面壁纸呈两色抖动，截图 `dev-config-0.9.8-desktop-level2.png`。

清除：执行「清除壁纸」后新文件被删除，配置中 `wallpaperPath` 键消失，桌面回退纸色，截图 `dev-config-0.9.8-desktop-cleared.png`。

重启：设置壁纸后 `force-stop` 并重新启动，壁纸与量化档位保持，文件未被清理，截图 `dev-config-0.9.8-desktop-restart.png`。

缺失文件回退：还原后的配置指向已删除的 `wallpaper_1792433694169.png`，桌面与锁屏均回退纸色且未崩溃，截图 `dev-config-0.9.8-lock-no-wallpaper.png`。

## 八、遗留

1. `clearWallpaper` 与 `clearLockWallpaper` 仍先删除文件再写配置；配置写入失败时路径指向缺失文件，按回退纸色处理，不会崩溃，与本次修复的替换路径风险不同级别。
2. `importTheme` 导入新壁纸时未删除被替换的旧文件，会产生未引用文件；属主题导入路径，未纳入本次范围。
3. `files/wallpaper/` 下 `wallpaper_1792377509385.png`（2026-10-19 10:38）为历史遗留，非本次产生，未清理。
4. 本次报告按要求写入 `_analysis/verify/0.9.8-wallpaper.md`，该目录不在任务声明的 `_analysis/team` 写作用域内，作为偏差记录。
