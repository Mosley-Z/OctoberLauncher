# 微读墨记内置与桌面组件重构开发方案

状态：待审阅，未开始实施。本文件只写方案与分期，不含代码改动。

## 一、决策记录

本轮四项指示按以下理解固化为方案前提。

1. 扫码录入采用 ZXing 生成二维码，设备不创建热点。所有微信读书相关功能以「微读墨记」为载体，接口密钥只存放在微读墨记的配置内，其他模块不保存副本。二维码录入做成可被任意页面调用的功能模块；任何微信读书入口在检测到未配置密钥时给出「打开二维码扫描录入」，录入完成后微读墨记内同步，设置页的密钥行显示已配置。
2. 目标是十雨桌面特供的内置版微读墨记：桌面卡片内容变成一个整体小组件，五形态切换方式与原来一致，不再以无障碍悬浮窗或单组件形式出现；功能、文字、版式与原卡片一致；微读墨记其余功能全部保留；从原版迁移的用户使用时无感。原版微读墨记代码保持不动，本机卸载原应用后用内置版测试。因此改动为三件：内置微读墨记、把桌面卡片改为十雨桌面组件、把墨台全部内容移入负一屏。
3. 删除组件 W01 阅读进度、W02 天气、W15 KOReader 月热力、W16 使用统计；W06 至 W14 在第二项改动中重写，此轮一并删除。图片组件支持选择多张，桌面点击轮播。
4. 整理模式布局面板的待定项按推荐值定稿，先做第一版。

## 二、目标与验收定义

### 2.1 密钥唯一存放

配置结构新增微读墨记配置节，接口密钥字段只此一处。

- 读写入口：设置页密钥行、二维码录入模块、所有微信读书数据请求。
- 其余模块与备份流程只读取状态，不复制密钥。
- 备份导出不含密钥（沿用 `LauncherConfig.withoutLocalCredentials` 的既有语义）。

### 2.2 二维码录入模块

新增可复用服务与页面，调用方只需要表达「需要密钥」。

- 未配置时的统一提示：弹窗文案「微信读书未配置」，两个按钮「打开二维码扫描录入」与「取消」。
- 已配置时调用方直接继续，不出现提示。
- 录入成功回调：写入配置、清空微信读书缓存、通知组件与页面刷新、返回调用方。

### 2.3 桌面卡片一致性

以微读墨记原卡片为版式基准，逐段还原。

- 基准尺寸 368×346，位于 480×800、219 dpi 屏幕上。
- 五形态：本周、本月、本书、本记、待办，切换方式与原版一致。
- 文字内容、字号层级、分隔线、底部统计行、成就行与原版一致。
- 组件槽为通栏，卡片按槽宽等比缩放并居中，超出部分不裁切文字。

### 2.4 墨台全部内容入负一屏

墨台三个模块各成一张负一屏卡片：阅读账单、阅读资产、阅读指纹。墨台设置项并入微读墨记设置页。墨台壁纸与导出的处置见第十二节待确认。

### 2.5 其余功能保留

阅读页、本书页、本记页、洞察页、设置页、待办页、实验室、遥控台、更新检查全部保留，作为内置版页面；待办形态依赖待办数据，随卡片一并实现。

### 2.6 组件清单结果

删除 12 项：reading、weather、koreader_month、usage、weread_covers、weread_month、weread_mark、weread_note、weread_stats、weread_bill、weread_rank、weread_fingerprint。

保留并合并后共 5 项：

| 组件 | 处置 |
| --- | --- |
| clock | 保留，吸收 clock_compact 的单行形态，组件内提供两种排版选项 |
| calendar | 保留 |
| image | 保留并升级为多图轮播，支持一次选多张、桌面点击切换 |
| placeholder | 保留 |
| weread_board | 新增，微读墨记整体卡片 |

旧配置迁移：被删除的微信读书类标识改写为 `weread_board`；reading、weather、koreader_month、usage 改写为 `clock`；clock_compact 改写为 `clock`。迁移在配置升级中一次完成，用户升级后桌面不出现「未安装组件」。

## 三、目标结构

### 3.1 模块划分

新增 Gradle 模块 `feature:weread`，职责为微读墨记的全部功能；`feature:content` 缩减为本地书籍、KOReader、天气与最近使用。

`feature:weread` 内部包结构：

| 包 | 内容 |
| --- | --- |
| data | 网关、同步、缓存、统计与笔记模型、待办存储、配置读写 |
| card | 卡面渲染：抬头、周体、月体、书体、记体、待办体、成就行、版式常量 |
| pages | 阅读首页、本书、本记、洞察、待办、设置、实验室、遥控台、更新 |
| negative | 墨台三张卡片 |
| key | 二维码录入服务、临时 HTTP 服务、令牌状态机 |
| widget | 整体组件、形态切换、命中区 |
| config | 微读墨记配置节与设置声明 |

依赖方向：`feature:weread` 依赖 `core:common`、`core:design`、`core:render`、`core:widget-api`、`core:data`；`feature:widgets` 不新增对 `feature:weread` 的依赖，整体组件由 `feature:weread` 自行实现 `WidgetProvider` 并注册；`feature:settings` 增加微读墨记设置分组，通过配置读写与 `feature:weread` 解耦。

### 3.2 契约扩展

`core:common` 增加以下内容。

- `WereadService` 接口：书籍、进度、统计、笔记、账单、资产、指纹、待办、设置读取；`AppServices` 增加一个服务字段与就绪检查。
- `WereadKeyEntry` 接口：`isConfigured()`、`openEntry(host)`、`onConfigured` 回调。
- `Destination.WereadHome`、`Destination.WereadKeyEntry` 与标签。
- `NegativeModule` 沿用现有契约，三个墨台卡片注册到 `NegativeModuleRegistry`。

同步节奏：书架全量分页同步、逐本进度批量拉取、笔记三阶段同步（书索引、想法、划线），缓存有效期沿用原版 6 小时；统计与账单按周期起点分键缓存六期。

## 四、数据层

### 4.1 接口

沿用原版网关 `https://i.weread.qq.com/api/agent/gateway`（`WereadMoji/net/WereadApi.java:41`），端点集合：

`/shelf/sync`、`/book/getprogress`、`/book/chapterinfo`、`/readdata/detail`、`/book/bestbookmarks`、`/user/notebooks`、`/book/bookmarklist`、`/review/list/mine`。

请求头 Bearer 携带密钥，`api_name` 与 `skill_version` 按现有 `WereadClient` 的写法保持一致。

### 4.2 模型

数据类：周期统计（总时长、天数、日均、逐日、最长、偏好）、书籍统计、笔记统计、账单、资产、待办、进度日志、卡片偏好、菜单偏好、页面偏好、成就偏好。

与现有结构的关系：`WereadStatsSnapshot`、`WereadNoteSnapshot`、`WereadBillSnapshot`、`WereadRankEntry`、`WereadShelfItem` 保留并扩展字段；价格与逐本资产为新增模型。

### 4.3 存储

- 配置：`LauncherConfig.weread`（密钥、卡片形态偏好、成就行开关、月历样式、摘录字号、墨台模块顺序、待办开关）。
- 数据缓存：`filesDir/weread/` 下的 JSON 快照与索引，按周期分文件，写入用临时文件替换。
- 笔记：书籍索引、划线、想法三份表，按书籍标识聚合。

### 4.4 旧数据导入

原版数据存于其应用私有目录，内置版无法直接读取。方案为一次性导入：

1. 原版提供笔记与统计导出（`WereadMoji/feature/NoteExport.java` 372 行），导出文件落公共目录。
2. 内置版设置页新增「从微读墨记导入」，选择导出文件后解析写入本地存储。
3. 密钥不参与导入，用户通过二维码重录一次。

导入映射表在实施阶段按导出格式确定，见第十二节待确认。

## 五、桌面卡片组件

### 5.1 版式基准

- 设计画布 368×346，绘制单位沿用原版「号 × unit」体系，等价常量落到 `core:design` 的令牌（字号、线宽、内边距、灰阶）。
- 组件槽宽 W、高 H：缩放系数 `s = min(W / 368, H / 346)`，画布以 `s` 等比缩放并水平居中；`s` 限制在 0.9 至 1.35，避免极小或极大槽位下文字失真。
- 槽高低于 300 像素时切换紧凑版：省略成就行与底部统计行，正文压缩为两行，其余元素与文字保持一致。

### 5.2 形态与内容

| 形态 | 内容 | 数据 |
| --- | --- | --- |
| 本周 | 抬头、本周总时长、天数与日均、七柱图、底部统计行 | 周期统计 WEEKLY |
| 本月 | 月历热力格、本月合计、上月对比、月排行 | 月报与月历 |
| 本书 | 封面、书名、作者、进度条、今日与累计时长 | 书架首本与进度 |
| 本记 | 最近划线、想法、书名、翻页 | 笔记与想法 |
| 待办 | 待办条目、完成状态、当日计数 | 待办存储 |

抬头含形态名、切换图标、刷新图标；成就行按偏好显示或隐藏。

### 5.3 交互

原版以八个独立触摸子窗承接点击，组件内改为命中区判定：

- 抬头名称区：切换到下一形态，循环顺序与本版一致。
- 切换图标区：形态选择浮层，列出五种形态。
- 刷新图标区：立即刷新当前形态数据。
- 正文区：进入微读墨记对应页面（本周与本月至统计页，本书至本书页，本记至本记页，待办至待办页）。
- 长按：打开组件库。
- 点击坐标按缩放系数反算到设计画布，命中区之间不重叠。

### 5.4 注册

- `WidgetCatalog` 新增 `weread_board`，分类 `WEREAD`，`refreshPolicy = EVENT`，能力 `WEREAD`，`label = "微读墨记"`，`description = "本周、本月、本书、本记与待办"`。
- 选择页的 `WEREAD` 分组只列该项，页面代码不改。
- `proguard-rules.pro` 增加 `WereadModule` 与组件类的保留规则。
- 应用装配增加 `com.shuiyu.octoberrain.feature.weread.WereadModule` 反射入口。

### 5.5 空态与未配置

- 未配置密钥：整卡绘制「微信读书未配置」与「打开二维码扫描录入」提示，点击进入录入。
- 已配置无数据：「暂无阅读数据」，五种形态共用。
- 单段无数据：该段绘制「—」，不改卡高。

## 六、墨台入负一屏

### 6.1 三张卡片

| 模块标识 | 名称 | 内容 | 数据 | 规模 |
| --- | --- | --- | --- | --- |
| weread_bill | 阅读账单 | 本周与本月时长、逐书时长、阅读天数 | 周期统计与账单 | 260 至 340 行 |
| weread_assets | 阅读资产 | 逐本时长、进度、收入与原价前五行 | 全量书架与逐本进度 | 220 至 300 行 |
| weread_fingerprint | 阅读指纹 | 七列四行灰阶指纹与连续天数 | 年统计与月报 | 140 至 200 行 |

指纹几何线稿版需要复刻 485 顶点资源（`fp_paths.txt` 530 行）与 817 行绘制代码，列为后续可选，首版用灰阶格。

### 6.2 注册与开关

- 卡片按 `FilesNegativeModule` 的范式实现，卡片内加载用令牌校验、`onResume` 重载、`onPause` 取消。
- 在 `NegativeSpecs` 追加三条开关，分组副标题同步；默认关闭，避免升级后负一屏突然变长。
- 顺序沿用 `modules` 列表，首版固定为书架、最近图片、阅读账单、阅读资产、阅读指纹。
- 墨台设置项（模块顺序、壁纸、导出）并入微读墨记设置页；模块顺序首版只提供固定顺序。

### 6.3 价格与资产缺口

价格链在原版为手填价、笔记价格索引、账单市场价、统计原价四层，内置版无对应录入界面。首版账单与资产卡片不显示价格与合计，只显示时长与条目；价格数据列为独立后续项。

全量书架：原版回包 462 KB、1175 本，现有数据层只取 40 本并补 8 本进度。首版资产卡片用现有 40 本；全量同步需要分页、并发预算与磁盘缓存，列为数据层第二阶段的独立任务。

## 八、密钥二维码录入模块

### 8.1 依赖

`gradle/libs.versions.toml` 增加 `zxing-core 3.5.3`，`feature:weread` 以 `implementation` 引入；R8 后安装包增量估计 250 至 400 KB。

### 8.2 服务端

- 纯 `ServerSocket` 实现，随机端口，绑定 `0.0.0.0`。
- 一次性令牌 128 位，页面地址 `http://<设备地址>:<端口>/k?t=<令牌>`。
- 两个路由：GET 返回录入页，POST 接收密钥；请求体上限 4 KiB，`Connection: close`，`Cache-Control: no-store`。
- 有效期 90 秒，尝试上限 5 次，成功即关闭；页面销毁、进程退到后台、超时三种情况关闭服务。
- 设备地址取自 `ConnectivityManager` 与 `LinkProperties`；无 WiFi 连接时页面显示「请先连接与手机相同的 WiFi」，并保留手动输入入口。

### 8.3 页面

- `WereadKeyEntryScreen`：二维码、地址文本、状态行、取消按钮。
- 二维码内容只含地址与令牌；页面提示「手机扫码后粘贴接口密钥」。
- 录入成功后写入配置、清空缓存、通知刷新、返回调用方并提示「密钥已保存」。

### 8.4 调用协议

任意入口在发起微信读书请求前调用 `WereadKeyEntry.isConfigured()`；未配置则弹窗提供「打开二维码扫描录入」与「取消」。设置页密钥行、阅读页、卡片点击、负一屏微信读书卡片统一经该协议处理。

### 8.5 复用边界

二维码生成、服务端、令牌状态机与页面都在 `feature:weread` 内，通过 `core:common` 的接口暴露；其他模块只依赖接口，不依赖 `feature:weread` 的内部类。

## 十、整理模式布局面板

首版按推荐值定稿。

- 位置：组件槽区域，左边界与四列网格一致，顶部从提示条下沿 49 像素处开始；固定位置，不拖动、不记忆。
- 尺寸：常规 420×346 像素；槽高低于 300 像素时使用 230 像素紧凑版，可完整落在 231 像素组件槽内。
- 内容四行：列数、行数、间距、尺寸，每行左侧名称与当前值，右侧减号与加号；数值与设置页四项同源，步进合并沿用 160 毫秒。
- 页码：面板内部提供「上一页」「1/3」「下一页」，绕开整理模式屏蔽横向滑动的手势限制。
- 底部：恢复自动、完成；恢复自动写回设置页的自动值。

## 十三、隐患与应对

- 数据层规模最大，原版 `NoteStore` 1834 行与 `BillScheduler` 778 行的逻辑需要按其行为重建，进度可能超出估算。应对：P1 先做可验证的最小集（书架、进度、月报、笔记），资产与账单在 P3 前补齐。
- 卡片一致性与缩放存在观感折衷，需要真机对照原版截图逐项调整。应对：P2 建立截图对照清单，每形态一张。
- 遥控台与待办引入新的权限与存储，可能影响启动耗时。应对：页面按需加载，数据初始化放到首次进入。
- 内置后应用体积与内存增加，需要设定上限。应对：P8 记录安装包增量与 PSS，增量超过 2 MB 或 PSS 超过 55 MB 时压缩资源与缓存。
- 原版工程保持不动，两侧并行期间密钥与缓存各自独立，测试阶段容易混淆。应对：本机卸载原应用，验收只在内置版进行。
