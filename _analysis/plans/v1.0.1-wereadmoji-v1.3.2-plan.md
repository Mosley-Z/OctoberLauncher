# 十雨桌面 V1.0.1 与微读墨记 V1.3.2-beta 同步开发方案

本文是内核化双宿主形态的实施方案。两仓同步推进：`D:\WorkBuddyStation\WereadMoji` 出 V1.3.2-beta（内核抽取、原版适配、共存静默、数据导出），`D:\DSHStation\OctoberLauncher` 出 V1.0.1（接入内核、负一屏即墨台、整体卡片、页面补齐、数据导入）。发布需明确验收指令，方案内只产出候选包。

## 一、目标

用户可单独安装微读墨记 V1.3.2-beta，在原生桌面与图墨桌面上使用时功能与当前版本一致；安装十雨桌面后，微读墨记自动隐藏图标并静默（卡片、通知、定时任务全部停止），功能与既有数据由十雨桌面内置版接管；卸载十雨桌面后，微读墨记恢复显示与运行。

十雨桌面未安装微读墨记时，内置版独立可用，密钥通过二维码录入，数据从空白开始。

## 三、内核契约

内核以 Java 源集交付，包名 `com.inkread.weekread.kernel`，对外只暴露四个接口与六个数据模型。

```java
// 宿主适配入口：内核不感知 Activity、窗口与屏幕尺寸
public interface KernelHost {
    Context context();          // 仅用于文件与缓存目录
    float scale();              // 宿主给出的排版缩放，1.0 对应 368×346 基准
    void requestRedraw();       // 数据变化后请求宿主重绘
    void openPage(String target);// 打开墨台、本书、本记等内部页面
}

// 渲染入口：宿主给出画布与矩形，内核按基准等比绘制
public interface CardSurface {
    Canvas canvas();
    int width();
    int height();
    int hitTest(float x, float y);  // 返回热区编号，未命中返回 0
    void onAction(int action);      // 热区动作回调
}

// 数据入口：内核只读宿主提供的数据仓库
public interface DataSource {
    ShelfSnapshot shelf();
    PeriodSnapshot period(String mode);
    List<BillItem> bill(String mode, int offset);
    List<AssetItem> assets(int sort, boolean folded);
    FingerprintGrid fingerprint(int bookCount);
    List<NoteItem> notes(int limit);
}
```

内核版本 `1.3.2-k1`，十雨侧记录产物 `weread-kernel-1.3.2-k1.jar` 与 sha256；内核改动按补丁号递增，契约破坏性改动按 `k2` 升号并同步十雨。

## 四、共存与静默

### 4.1 十雨侧的检测

十雨启动时（`OctoberRainApp.onCreate`）查询 `com.inkread.weekread` 的 `versionCode`：未安装则跳过；版本低于 1.3.2-beta 则提示「需要升级微读墨记才能迁移」；版本满足则进入一次性迁移流程。

迁移流程：显示进度页，调用 `Intent` 打开微读墨记的导出 Activity，传入十雨 `cacheDir` 下的临时目录 Uri 与一次性令牌；微读墨记写出清单与数据包后返回结果；十雨校验、导入、写入迁移元数据，最后提示「微读墨记已静默」。

### 4.2 微读墨记侧的静默

检测到 `com.shuiyu.octoberrain` 且其版本不低于 1.0.1 时进入静默，四个动作：

1. 通过 `PackageManager.setComponentEnabledSetting` 禁用启动别名，图标从桌面消失。需要把启动入口改为 `activity-alias`，`MainActivity` 只保留内部入口。
2. 禁用无障碍服务组件并停止悬浮窗，卡片与墨台入口同时失效。
3. 停止卡片刷新与账单调度，清除已发通知，冻结数据写入。
4. 写入 `silent_since` 与十雨版本号，供恢复判断。

恢复条件：十雨包不存在时，在应用启动、`BOOT_COMPLETED` 与十雨的卸载广播（不可依赖，作兜底）三条路径上检查并恢复图标与无障碍服务组件，清除静默标记。静默期间原版数据冻结，恢复后以冻结时间点为准，数据以十雨内为准的差异由用户决定是否回导。

### 4.3 两应用共存矩阵

| 状态 | 微读墨记 | 十雨桌面 |
| --- | --- | --- |
| 只有微读墨记 | 完整功能，原生与图墨桌面可用 | 未安装 |
| 只有十雨桌面 | 未安装，内置版从空白开始，密钥二维码录入 | 完整功能 |
| 两者都安装且版本满足 | 静默：无图标、无卡片、无通知 | 内置版接管，数据已导入 |
| 两者都安装但微读版本过低 | 正常显示 | 内置版从空白开始，提示升级后迁移 |

## 五、数据迁移

清单字段：`schemaVersion=1`、来源版本、`versionCode`、逐文件 `sha256`、条目数、导出时间、是否加密。

数据包按来源分类：`index.json`、`nt_<id>.json`（220 个，约 2.3MB）、`ni_<id>.json`（55 个，240KB）、`shelf.json`（67KB）、`shelf_ids.json`、`bills.json`、`assets.json`、`stats.json`、`menu_notes.json`、`menu_prices.json`、`menu_progress.json`、`todo.json`、`achievement.json`。

十雨内落位：书级数据进 `filesDir/weread/`，密钥进 `LauncherConfig.integrations.wereadApiKey`，迁移元数据进 `LauncherConfig.wereadMigration`（来源版本、导入时间、清单摘要、是否完整）。配置版本 `CURRENT_VERSION` 升到 8。

加密：导出包用 AES-GCM 加密，密钥随机生成后经 `Intent` 额外字段传给十雨，只存活于单次迁移；清单明文保留摘要用于校验。

校验与回滚：先写 `filesDir/weread/tmp-<时间戳>/`，逐文件校验 `sha256` 与条目数，通过后原子替换，保留七天备份；任一校验失败则删除临时目录并保持空白状态，界面提示失败原因。

幂等：迁移元数据存在且摘要一致时跳过重复导入；用户可在设置中手动重新导入。

## 六、负一屏即墨台

模块顺序默认值：`bookshelf`、`negative_files`、`weread_bill`、`weread_rank`、`weread_fingerprint`，五项全部开启。

`NegativeModule` 增加 `onDestroy()`、`defaultEnabled`、`orderHint`；`NegativeHost` 增加 `context` 与 `widthDp`；`NegativePageConfig` 增加 `forms` 与 `cardOrderInitialized`。负一屏顶部增齿轮入口，进入 `Destination.NegativeSettings`，页面内提供五项开关、上移下移，以及墨单的 13 项 `menu_*` 配置（原应用内没有用户可达界面，内置后必须补齐）。

三张墨台卡片按负一屏宽度自适应，墨单保留周月切换、周期导航、摘录与读书双皮肤、收入三档口径与合计；阅读资产保留三键排序、折叠十本、双皮肤、三条过滤、长按移出与恢复、长按录价；阅读指纹保留四档字号、选书上限五十、485 顶点与 256 级墨量。

## 七、整体卡片

`weread_board` 单组件承载原卡片五形态，默认本周（按原设置），标题区点击循环切换，形态写入 `NegativePageConfig.forms` 并在负一屏卡片与组件之间共享。

缩放以 368×346 为基准按槽宽等比，字号与热区同步缩放，最小可读宽度 320dp。热区由内核计算，宿主通过 `WidgetHitRegion` 转发坐标；`WidgetView` 增加 `hitRegions()` 与带坐标的 `onLongPress(x, y)`。

原「切应用、翻页、点击图标让位」与桌面探测在十雨内删除，改为编辑模式下隐藏；隐藏时长设置保留。原卡片标题、更新于、底部左右四类点击全部保留。

## 八、页面

保留原应用全部页面：阅读页五形态与周期选择、本书页、本记页、设置、待办、帮助。墨台改为负一屏，不再作为独立页面。遥控台只在手机端出现，内置版不移植，原版应用在未静默时继续提供。应用内更新由十雨更新通道替代。

## 九、密钥

内置版是独立产品，密钥存 `LauncherConfig`，由二维码录入；原版密钥存 `cfg.api_key`，迁移时随数据包导入。两者都支持换钥清数据，内置版清空范围为 `filesDir/weread/` 下全部书级数据并清除缓存。

二维码录入沿用第一版方案：设置页启动随机端口与一次性令牌，二维码内容指向本机地址，手机在同一热点下粘贴密钥，令牌单次有效九十秒，尝试上限五次。

## 十、分支与发布纪律

微读墨记：从 `beta` 开 `feat/v1.3.2-beta`，内核改动与原版适配分开提交；`version.properties` 单一版本来源；构建仍用 `tools/build.sh`，签名密钥在库外；产物 APK 与 sha256 写入 `_analysis/verify/`。分支保留，不合并回 `beta`，直到十雨 V1.0.1 验收。

十雨桌面：从当前工作区开 `feat/v1.0.1`；内核以固定产物进入 `libs/`，不使用同机路径引用；门禁沿用 `gradle --offline testDebugUnitTest check :app:assembleDebug :app:assembleRelease`。

两包发布都需 Doow 明确指令；本方案只产出候选包与验证记录。

## 十二、验收矩阵

设备：S4 480×800、552×768、824×1648 三档。组合：仅微读墨记（原生桌面、图墨桌面）、仅十雨桌面、两者共存迁移后、微读版本过低。

必测项：迁移完整性与幂等；静默后图标消失、卡片消失、通知清空；卸载十雨后图标与卡片恢复；内置版五形态切换；负一屏五模块开关与排序；三档设备卡片缩放；密钥二维码录入；换钥清数据；门禁与静态检查零新增告警。

## 十三、隐患与应对

内核抽取期间原版功能可能出现回归，用原版回归清单（卡片五形态、墨台三模块、待办、设置）逐项对照，回归清单随 A2 一并冻结。

静默依赖组件开关，部分系统对 `activity-alias` 开关有延迟，恢复路径需要真机验证；备用做法是在应用内首屏提示「已静默」并保留手动恢复开关。

数据导入失败会留下半成品临时目录，用启动清理任务删除超过二十四小时未完成的目录。

内核产物与十雨版本耦合，内核升级必须成对发布；十雨设置页显示内核版本号，便于排障。

微读墨记静默期间数据冻结，卸载十雨后可能与十雨内数据不一致；方案只保证恢复到冻结时间点，回导差异留到 V1.3.3 评估。
