## 根因与目标闭环

DesktopEntries 已有稳定 key，但长按与美化页用 packageName 判断可换图标；IconStore 的特殊入口分支调用 loadSpecialIcon，后者只画默认字形，未读取覆盖图。不能只加菜单，必须打通存储、加载、失效及主题。

目标：长按设置/文件或在美化页选中 → 使用现有图标选择/图片流程 → 桌面与预览立即一致 → 重启保留 → 恢复默认；主题保存与恢复包含这些覆盖。

## 实施步骤与兼容契约

1. 集中定义图标目标解析：普通应用沿用现有包名存储键，两个特殊目标使用 special:settings / special:files；不要给所有普通应用键自动加 app: 前缀导致旧配置失效。优先轻量辅助类型/函数，避免为两个入口另造平行存储系统。
2. IconOverrideStore 接受统一目标标识，私有文件名安全映射并核查碰撞；旧包名覆盖图、清单、主题文件保持可读。图标路由即便暂留 packageName 字段名，也应明确其目标语义，并且不对 special 调用 PackageManager。
3. 长按两个入口提供“更换图标”和按需出现的“恢复默认图标”，保留原有打开/移动能力；特殊入口不显示卸载/系统应用详情等包名操作。
4. 美化页两个入口可选、显示真实图标与已替换状态，复用现有选择流程；名称取稳定入口标签，不要求已安装应用目录有匹配包名。IconPicker、Preview、BeautifyAppRow 等各消费端统一使用目标解析。
5. AppCatalogImpl.loadSpecialIcon 先取覆盖图，缺失/不可解码时回退原齿轮/文件夹；覆盖变更联动 catalog 内存/磁盘缓存和 Home IconStore。核查大小、键大小写、version 订阅及异步代际，恢复后不被旧请求写回。
6. 核查主题保存/应用/导入导出/重置：不得按安装包过滤丢失 special 键；预览与桌面一致。只处理现有主题能力，不引入新的文件格式；旧主题正常，清空与恢复默认语义一致。
7. 文件入口若默认隐藏，美化页保持既有可见入口规则，验证可通过已有显示设置启用后更换；不擅自修改用户隐藏/排序选择。
