## 二、行为说明

### 刷新策略

`RefreshPolicy` 成为唯一整刷入口，`RefreshReason` 区分五种来源：手动、定时、退出应用、外观变化、内容变化。手动与退出应用执行黑白两次闪烁（90ms 与 120ms），其余来源执行单次快速闪烁（70ms）。闪烁结束后统一登记到 `RefreshScheduler`，定时调度与其它来源共用同一时间基准，`millisSinceFullRefresh()` 从未整刷时返回 `Long.MAX_VALUE`。

`MainActivity` 在 `onPause` 记录离开时刻，`onResume` 时若间隔不小于 1500ms 且 `tray.refreshOnAppExit` 开启，按 `refreshOnAppExitDelayMs` 延迟请求 `APP_EXIT` 整刷。熄屏离开时跳过，避免与锁屏叠加闪屏。

托盘设置页新增三项：返回后刷新开关、延迟滑条（50..500ms，25ms 步进）、距上次整刷摘要与立即整刷入口。

### 通知

`NotificationItem` 增加 `appLabel`、`groupKey`、`conversationTitle`、`isSummary`、`isOngoing`、`isGroup`、`count`。服务层从 `Notification.extras` 读取会话标题与分组摘要标记，摘要条目按配置剔除；同一会话键的连续通知合并为一条并累计条数；`foldByApp` 开启时同包条目折叠为一条代表条目。桌面图标角标读取 `NotificationCenter.visibleItems(config)` 按包名累计条数，上限由 `badgeMax` 控制。

托盘通知卡改用可视条目，首行显示应用名与时间，折叠条目在标题后显示条数。新增通知展示设置页，覆盖折叠、归并、摘要过滤、应用名、角标开关与上限。

### 图标包

`IconPackResolver` 读取图标包 APK 内 `res/xml/appfilter.xml`（缺失时读 `assets/appfilter.xml`），按 `ComponentInfo{包名/活动名}` 精确匹配，再按包名回退，drawable 与 assets 双来源查找，输出目标尺寸的透明方形位图。

`AppCatalogImpl.loadIcon` 顺序为内存、图标包、磁盘、系统图标；内存键与磁盘文件名均带图标包标识，切换图标包后不复用旧图。`AppearanceRepositoryImpl.iconPacks()` 枚举已安装的 ADW 与 GO 图标包，标识统一为包名。

### 桌面可调项

`DesktopConfig` 新增列间距、行间距、图标边长、名称字号、横向位置、首页行数；`DesktopMetrics.compute` 以配置值覆盖令牌推导值，行距均分保留原有 `fitRows` 逻辑。设置页暴露六项，写入后即时重算布局。

### 长按分级

`longPressEditMs` 拆为 `longPressMenuMs`（默认 400ms，打开单元素或空白菜单）与 `editHoldMs`（默认 1200ms，进入整理模式）。旧配置经 `ConfigMigration` 从单一阈值迁移：旧值小于 800 时按半值与全值拆分，否则取 400 与 1200。

长按分级真机验证：按住图标约 0.9 秒弹出条目菜单；按住空白约 1.5 秒进入整理模式并显示横幅。

### 主题令牌

`ThemePalette` 定义八个颜色字段与四套预设（墨、纸、夜、高对比）。`ThemeTokensCodec` 把配色与外观字段编码为 JSON 字符串，存于 `AppearanceConfig.themeTokensJson`；解析失败回退默认预设并记日志。`InkColors` 由常量改为可写对象，属性名保持不变，全库引用点无需改动。

### 最近任务与使用统计

`RecentsRepository` 基于 `UsageStatsManager` 查询最近 24 小时前台事件并按包名去重，另查询今天、本周、本月的应用时长；无权限时返回空列表。页面提供两个页签、图标与相对时间、区间切换与总时长，支持方向键移动、左右切换页签或区间、回车启动、返回键交宿主。

### 钟面样式

`ClockFace` 定义五项：大字、上下、翻页、方框、指针。`ClockStyleScreen` 以 120dp 方形预览渲染五项供选择，写入 `AppearanceConfig.clockFace`。

### 备份恢复

备份包为 zip，含 `config.json`、`theme.json`、`manifest.json`。导入时执行配置迁移、合并主题令牌，清单缺失或来源包不同给出提示。页面提供导出、从文件恢复、仅恢复主题三个动作。

### 负一屏书架

`NegativePageConfig` 控制启用、来源（微信读书书架、本地书架）、条目上限、是否显示进度与封面。首页在第一页继续右滑超过阈值时进入负一屏；负一屏内右滑或左滑返回桌面，点击条目打开对应读书应用。

书架数据来自 `ContentSource.wereadShelf` 与 `bookshelf`，前者依赖内容设置中已配置的微信读书密钥，未配置时页面显示配置引导文案。

## 三、验证

构建：`scripts/build.ps1 -Offline` 通过，`clean assembleDebug` 成功产出 `app-debug.apk`（3.16MB）。

单元测试：四个模块共 62 个测试，61 通过、1 跳过（`MonthGridTest` 的周一起始用例，见第四节），0 失败。测试通过后 `--offline` 模式因 `junit:4.13.2` 未进入本地缓存而失败，首次需要联网下载一次。

真机核对：设备 S4（480×800 墨水屏手机）。桌面渲染、首页右滑进入书架页、书架页左右滑返回、长按条目菜单、长按进入整理模式、托盘展开均正常。截图存于 `_analysis/shot-*.png`。

## 四、已知限制与待确认事项

`TimeUtils.kt:142` 的 `(firstDayOfWeek + 6) % 7` 实际按周日起始排列月历首行，与类注释声称的周一起始不一致。修正为 `(firstDayOfWeek + 5) % 7` 会改变 KOReader 月热力网格的起始列；`MonthGridTest` 中对应用例已标注跳过，修正后解除即可。

`DesktopMetrics.slotAt` 宫格分支只校验左边界，触点超出右边界时收敛到最后一列而非返回未命中。是否改为严格未命中取决于触摸语义的取舍，测试按现状记录。

通知折叠逻辑位于 `NotificationCenter` 的私有方法内，依赖 `AppServices` 与 `Application` 上下文，纯 JVM 无法测试。可抽出内部纯函数对象后补断言。

`iconPackId` 与导入主题的伪标识 `icon:名称` 语义已统一为图标包应用包名；主题目录中的旧伪标识记录不再作为图标包呈现。

切换图标包后 `filesDir/icons` 内的旧前缀文件未清理，磁盘占用随切换次数增长，后续可补清理策略。

负一屏当前为空状态时无插图，书架条目为三列宫格、封面按 3:4 裁剪；手势阈值与首页共用 `swipeMinDp`，细节待试用反馈。
