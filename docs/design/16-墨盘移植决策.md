# 墨盘能力移植决策

本文件记录 0.9.4 至 0.9.5 移植墨盘能力时需要裁决的事项与结论。依据为 `_analysis/team/mopan-port-plan.md` 的逐文件清单、`docs/design/15-V1.0开发计划.md` 的阶段划分与 D1 至 D7 决策。所有结论按可回溯原则给出，实施中如遇与源码事实冲突的情形，以源码为准并在此追加修订记录。

## 一、提供者归属

`Destination.Files` 由 `feature:files` 的新 `FilesModule` 注册，`feature:content` 的 `ContentModule` 不再注册该目标。旧 `feature/content/.../ui/FilesScreen.kt` 保留到新浏览页通过真机验收，随后删除；其图片目录能力迁入新模块的初始目录选择，书籍与阅读相关能力留在 `feature:content`。

`FileLibrary` 继续留在 `feature:content`，新模块通过 `AppServices` 读取书籍目录与图片目录，不复制实现。

## 二、导出组件

保留两个薄 Activity，声明在 `feature:files/src/main/AndroidManifest.xml`：

- `PhotoEntryActivity` 承接外部 `ACTION_VIEW` 与 `image/*`，解析 Uri、必要时复制到缓存、承载查看器界面。
- `PickEntryActivity` 承接 `GET_CONTENT` 与 `OPEN_DOCUMENT`，返回 content Uri，携带 `OpenableColumns` 的显示名与大小。

进程内查看与选图不走 Activity，改走路由参数：`Destination.PhotoViewer(paths, index)` 与 `Destination.FilePicker(mime)`。选图入口在 0.9.4 仍由系统选择器承担，模块内选择器随任务 4.4 单独切换，避免同时改动 `AppServices.picker` 契约。

## 三、分享 authority

采用方案 A：复用现有 `androidx.core.content.FileProvider`，authority 保持 `${applicationId}.files`，在 `app/src/main/res/xml/file_paths.xml` 增加 `<external-path name="files_share" path="." />`。分享用 `FileProvider.getUriForFile` 生成地址并临时授予读权限。二次存储卷的文件先复制到缓存再分享。墨盘 `OutProvider` 不移植。

## 四、字号与几何

文件页几何基准由整屏改为宿主内容区 View 实测宽高，密度取 `DeviceProfile.density`。字号统一到桌面令牌：标题 17sp、正文 14sp、辅助 12sp。墨盘正文 11sp 的排版不再保留，行数与信息密度按新字号重算，三档设备各做一次截图核对。

描边取 `InkTokens.stroke`，不沿用墨盘按密度取整的 1px 规则。网格固定 4 列 4 行、每页 16 项；824 宽度下缩略图随之放大，宽度余量留给图片预览，不改为 5 列。

## 五、相册数据源

相册以 MediaStore 为主，目录扫描作为兜底。媒体权限缺失时降级为只读媒体模式，仍可浏览目录。索引在启动后异步建立，文件写后增量更新。

## 六、编辑输出

输出目录为 `Pictures/十雨桌面`，文件名为 `原名-编-yyyyMMdd-HHmmss.png`，重名以序号追加。长边按内存档位取 1600 或 2400，编码为 PNG。旋转标记沿用 `edited_rotations` 键并加模块命名空间前缀。

## 七、壁纸相关

按 D4 删除墨盘的壁纸导出与自动设置能力，查看器不提供「导出壁纸」入口。锁屏密码界面壁纸由 0.9.8 单独实现，复用图片选择与量化管线。

## 八、权限

继续依赖 `MANAGE_EXTERNAL_STORAGE`（D3），Android 11 及以上引导「所有文件访问」。相册在仅有该权限时直接查询 MediaStore。上架应用商店时的政策评估列入 1.0.0 发布准备。

## 九、入口

文件能力从桌面文件页进入，0.9.4 不新增独立桌面图标。图片能力在文件页内以图片分类呈现，0.9.5 增加相册入口与相册页。外部 `ACTION_VIEW` 与选图入口作为系统契约保留。

## 十、模块偏好

文件页局部偏好（视图、隐藏文件、排序键与方向、最后路径）写入模块内 `SharedPreferences`，文件名为 `files_prefs`。不扩展 `LauncherConfig` 的序列化结构，避免配置版本与迁移逻辑扩散。如果后续要求随备份迁移，再增加 `files` 节点并同步备份字段白名单。

## 十一、批次与依赖

| 批次 | 内容 | 版本 | 前置 |
| --- | --- | --- | --- |
| P0 | 解码、抖动、缩略图缓存的核心能力 | 0.9.3 | 无 |

| P2 | 浏览与缩略图：浏览宿主、网格页、列表页、预取 | 0.9.4 | P1 |
| P3 | 查看与选图：查看器、外部入口、选图、分享 | 0.9.4 | P2 |
| P4 | 编辑与相册 | 0.9.5 | P3 |

P1 与 P2 合计约 4,048 行 Java 的等价工作量，按单人 16 至 19 人日估算；团队并行时以文件写作用域隔离，同一模块内按批次串行。
