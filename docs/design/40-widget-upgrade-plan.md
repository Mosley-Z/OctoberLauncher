## 2. 时钟与月历

用户2026-10-25最新要求覆盖最初“六款不作为独立组件”的方案：A–F分别注册为固定样式组件，通过“长按组件 → 选择组件”直接选择，与既有组件库及顺序清单同源，不另造选择页面。

| 样式 | provider ID（固定clockFace为去掉clock_的后缀） | 形态 |
| --- | --- | --- |
| A 书页数字 | clock_book_page | 衬线大数字 |
| B 分隔时分 | clock_divided | 时、分以竖线分隔 |
| C 点阵时刻 | clock_dot_matrix | 点阵数字 |
| D 书房指针 | clock_study_dial | 十二数字表盘，默认无秒针 |
| E 中文时刻 | clock_chinese | 中文时间表达 |
| F 时日并排 | clock_time_date | 左侧上下时分，右侧年月日与星期 |

六个provider复用ClockWidget固定face构造，选择后保存widgetId；旧clock及appearance.clockFace继续支持，旧五款与已保存选择保持。删除“设置 → 桌面组件”内钟面区、字体/12小时制控件、独立ClockStyleScreen及对应路由/无消费者声明，已有clockFont/twelveHour值与有效消费者保留，不迁移清空。新增样式默认按分钟刷新，点阵固有结构保留，宽窄尺寸均需可读。

时间与日期从同一个本地Calendar生成不可变快照，各条目复用同一钟面绘制和字体规则。已有指定钟面字体优先；默认下A/D/E/F使用系统衬线、B等宽，其他沿原默认，点阵保持结构。

A/B/F在默认字体下将时间数字横向加宽18%，以接近设计稿的宽字形；日期不加宽。用户明确指定钟面字体时保留该字体原字形。预览与桌面使用同一规则，不新增字体依赖或页面。

D书房指针的数字刻度圈半径扩大约12%；指针长度、角度及粗细保持。小尺寸允许日期换行，紧凑指针继续采用左侧表盘、右侧日期。

E中文时刻分为小时、年月日星期、分钟三个区域。小时和分钟逐字自上而下竖排，字形正向；日期保持横排居中，独立增大目标字号。小时永远两字且固定24小时值：零时至九时、一零至二四；分钟逐位两字。段距随可用高度调整，时分共用字号，矮槽位统一适配避免挤压。最新规则与字号纠正见[本轮验收](../acceptance/2026-10-25-ux142-review-refresh.md)。

F右栏年月日星期在栏内左对齐，并增加距分隔线的间距。系统字体与Windows稿字形不同，验收关注结构、比例、对齐和可读性。

最新直接选择入口与E/F结果见[直接选择钟面验收](../acceptance/2026-10-25-ux140-direct-clock-picker.md)，此前验收保留当时版本及边界。

本轮四项微调见[2026-10-25验收记录](../acceptance/2026-10-25-ux140-clock-adjustments.md)；[前轮验收](../acceptance/2026-10-24-ux140-clock-styles.md)保留当时版本与结论。

原“日历”显示名称改为“月历”，保留`calendar`身份、配置和已选状态。

## 3. 待办周历

新增独立组件“待办周历”，横竖屏始终为七列。箭头独立大字，侧栏32dp、行高36dp为目标，短小尺寸按比例收敛；配置日移在IO串行保存，可见窗口只在真正重新进入时复位。周历接入现有分钟刷新以更新跨日标记；详见[审查整改](../acceptance/2026-10-25-ux141-review.md)。

| 区域 | 内容与操作 |
| --- | --- |
| 第一行 | 左侧年月，右侧“＋ 添加待办”；复用现有录入能力，默认今天，日期和时间可改 |
| 第二行 | 单字星期与左右箭头；每次移动一天，整列日期及待办一同移动 |
| 第三行 | 日期只显示日数字与左右箭头；每次切换七天，保持星期排列 |
| 内容区 | 各日期对应待办；三行表头固定，七列内容整体上下滚动 |

第二行右箭头令起始日减1：`一19…日25 → 日18…六24`；左箭头令起始日加1。第三行右箭头令起始日加7，左箭头减7。必须载入进入窗口的新日期及待办，不能只循环原有七列，也不修改待办日期。

跨月标题显示“2026年10–11月”，跨年显示完整年月范围。今天的日期数字加圆圈，对应星期字加粗；窗口不含今天时不高亮其他日期。日期运算使用本地日历日，不能以固定86400秒推进，需正确处理跨月、跨年及夏令时。

默认状态策略：保存用户选择的起始星期；重新进入或重启时回到包含今天的七天窗口。临时查看日期和内容滚动位置不跨重启恢复。这是方案补齐的可逆默认设计，并非用户逐项指定；初次采用周一开始。

### 待办数据与排版契约

周历与十雨内微信读书组件共用`WereadTodoHost`及同一存储，属于十雨内部联动，不承诺与微信官方App云端待办同步。

仅展示有日期且落在可见七天内的待办。任一入口新增、修改、删除、勾选或取消勾选后，另一入口同步更新；无日期待办仍保留在原待办界面。

每天独立排序：未完成先于已完成；同完成状态按时间早到晚，无时间排在有时间之后；同时间保持原`order`稳定。周历只做展示投影，不把排序写回原手工顺序。

勾选框可直接点击。有明确时间时，“勾选框＋时间”独占一行，正文从下一行开始；无时间时勾选框与正文首行同行。正文续行均对齐正文起点，形成悬挂缩进。内容换行而不通过缩小字号塞满。

## 4. 其他页宫格与关闭组件补位

其他页新增横屏3行4列、竖屏4行3列两种可选规格，方向独立保存；保留既有选择，首页继续独立布局。桌面、布局预览、美化入口及全部分页消费者必须采用同一结果，应用相对顺序不变。

在组件库选择“关闭组件”后，释放组件空间并重新布局、分页，后页应用自然前移；横屏同时释放64:36组件分栏，应用使用整页。页码须收敛至有效范围，重新启用时恢复所选组件布局。仅退出组件库、未改选择时不触发重排。列表模式沿用原布局语义，不强改为宫格。

## 5. 组件清理与图片手势

删除使用统计组件的注册与实现。旧配置当前选中`usage`时迁移为关闭并重排，不自动替换其他组件；旧轮换列表清除`usage`。其他仍有消费者的统计能力与权限保留，仅清理确认无残余消费者的部分。

删除宿主滑动切换不同组件的设置与处理。组件库决定当前组件；旧`widgetCycleIds`不再作为轮换或占槽来源，保留有效当前ID，清退`usage`，未知值沿用既有处理且不能留下空槽。旧`widgetSwitchGesture`停用。

微信读书内部形态按钮、待办内容滚动和书籍轮播继续保留。宿主不得抢占这些内部操作。

图片组件设置增加“滑动切图”：关闭、左右、上下、上下左右。左/上滑下一张，右/下滑上一张，首尾循环；单图不切换。保留自动轮播和现有点击语义，手动换图后重新计算轮播间隔，取消操作不切图。

新图片手势字段默认关闭，不从旧组件轮换手势推断图片偏好；这是本方案补齐的默认策略。旧图片、路径及解码失败继续沿用现有语义。

## 6. 本书与沉浸轮播

两处均为左滑使右侧书进入中央，右滑使左侧书进入中央；未达到阈值时回位。封面、书名、进度与点击打开目标须始终指向同一本书。

复用现有双向轮播，排查宿主手势抢占，不新增另一套轮播实现；保留现有首尾及循环语义。验收覆盖单书、两书、多书、两方向、取消与阈值边界。

## 7. 沉浸统计

今日阅读时长使用账号当天所有书籍的官方按日汇总，切换中央书籍不改变数值；沿用现有阅读/收听官方口径，不另行承诺排除听书。

官方[`readTimes`说明](https://github.com/Tencent/WeChatReading/blob/main/skills/readdata.md)提供周/月按日总秒数；秒到分钟只转换一次，不累加重叠周/月结果、单书时长或截断排行榜。刷新、跨日、失败及缓存消费须一致；数据缺失显示“—”，只有明确为0才显示0。

连续阅读天数优先绑定官方返回中语义明确的直接字段。公开文档未列出此字段；`readDays`是周期有效天数，不能直接作为连续天数。

无直接字段时按用户已接受的回退方案，从官方每日数据推导：单日达到60秒才有效；今天不足则从昨天起算，今天达标则从今天起算，遇明确不足60秒的日期终止。历史缺口不能当0，也不能呈现为完整连续天数；优先复用缓存，必要时有限补齐缺口，不扫描全部历史。

核查接口只记录技术字段与结构，不记录正文或Key。现有`ImmersiveStatsReader`已有每日总量缓存与连续推导，实施需追查实际数据来源、刷新和阈值；不能预先断言当前偏差来自单书统计。
