# 需求对接与闭环交付约定

生效：2026-10-22。来源为本轮 FIX 接管审查；适用于 DSH 和后续接手者，用户最新指令优先。它细化 [35 开发流程](35-development-workflow.md)，不增加普通可逆操作的审批。

## 本轮为什么发生偏差

- 原需求指定“行数旁边”，实现却变成单独的书源行；实现者把布局约束当成可自行调整的样式细节。
- FIX001 要求最近阅读独立于书源开关，FIX002 又明确只放在本地书源。实现者把“独立”延伸为两书源均显示，没有区分数据可访问性与展示归属。
- 抽出 ReaderRelayout 并通过纯规则测试，不代表搜索/书签等异步入口已经登记完成回调；实际仍有旁路。
- 新字段有默认值，直接读解码对象无法判断原始字段是否缺失；缺失与已选择默认值被混同。合并 v8/v9 迁移也扩大了升级影响。
- 三卡已开发而状态仍 TODO，接手者不能靠卡片判断源码阶段；“主要设备验证完成”也没有逐条对应触发条件和最终 APK。

这些是源码、卡片与验收之间的具体缺口，不推断开发者动机。本轮接管者也存在先构建、后补全局入口/缓存清单导致重复构建的问题；应先完成影响清单再批量集成。

本轮起草者也需改进：跨卡更改同一概念时应在卡首集中给出最终行为；“两源全关”属于旧模型，搬迁后必须翻译成新界面的可观察场景。

## 开工前留下六行需求回读

写进当前 TASK 的执行记录，不要求再问用户一次。只有产品含义确实缺失才澄清。

1. 最终入口在哪里；哪些旧入口删除、兼容跳转或保留。
2. 控件具体位置和操作方式；“旁边/同一行/单选”等明确约束逐字保留。
3. 哪些内容在哪个状态显示，哪些状态不显示。
4. 新状态写入哪个字段；实际消费者有哪些；哪些相关功能不得受它影响。
5. 旧值如何迁移、退出与重启如何保留；多卡对同一字段的最终口径以哪张卡为准。
6. 每条要求用什么触发条件、可观察结果与证据判定完成。

## 开发与验收的执行方式

- 对共享逻辑做调用点清单：方法抽取完成后搜索所有状态写入/直接赋值，确认没有旁路。规则单测与真实 Android 适配入口分开验证。
- 迁移先区分原始字段是否存在，再解析值；正常加载与备份导入使用同一规则。保留独立历史迁移，不能为了缩短函数而让已升级版本重复迁移。
- 性能优化保留语义：切换来源只切展示，不清空两侧有效快照；微信读书与本书共用原盘缓存和book刷新入口，数据版本通知只重读本地；本地目录仍仅标题手动扫描。独立自动模式已被FIX006取消。不要把读取快照和获取新数据混成一个 refresh。
- 设备用例名称包含触发条件。“空闲尺寸变化”“搜索忙碌尺寸变化”“真实旋转”分别记录；wm size 不能冒充实体旋转，书签回归不能替代重排。
- CLI 返回成功只代表命令执行；冷启动等布局就绪后再点击。Canvas 编号必须来自当前包、当前截图；图片选择成功可能自动返回，不盲目追加 back。长按用 scripts/android-ui.ps1 的 tap -Label -HoldMs。
- 接手、完成阶段和换任务时更新卡片负责人/状态/证据；READY_FOR_REVIEW 可以有明确未覆盖，DONE 不能隐藏卡内未完成条件。缺设备就写待验，不把另一设备尺寸模拟当补齐。
- 报告按需求 ID 写预期、实际、证据、未覆盖和测试状态恢复；不要只列修改文件或“主要通过”。同一业务修正后的最终 APK 才用于本轮结论。

## 机器检查与人的责任

scripts/check-project-docs.py 已覆盖 RD 与 FIX 卡的状态、必需交接字段、索引和跨系列依赖无环。它不证明实现符合需求，也不证明设备通过。评审仍需对照上表的反例和证据。

本轮来源：[FIX 接管验收](../acceptance/2026-10-22-fix-takeover-codex.md)。后续规则变化应链接新证据，不重复复制整段历史。

FIX004 增量经验：持久快照的成员列表与阅读进度分开更新；封面渲染也属于联网消费者。序列化优先显式 serializer()，在最终混淆包核对同一快照，不能用 debug 正常代替 release 验证。

## FIX005/006 用户最新覆盖及反思

微信读书书架与桌面本书共用缓存和刷新，不再保留独立自动设置/计时器；书封底部进度条/沙漏删除，右上百分比保留。此前FIX004由Codex引入的独立快照漏掉小组件一致性验证；今后先列权威数据源及全部消费者，先排序后限量，以同一目标书核对成员和排名，避免只验“能刷新”。来源：[本轮验收](../acceptance/2026-10-22-shared-shelf-refresh.md)。
