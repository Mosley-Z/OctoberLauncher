## 1. 产品结构与入口

普通桌面保留宫格/列表，新增沉浸模式。模式与宫格/列表不是同一个枚举：退出沉浸恢复原普通桌面形态、顺序与容量。微信读书开启、Key可用、网络可用、显示模式分开表达，不用一个布尔值代表四件事。

| 入口 | 最终职责 | 旧入口处理 |
| --- | --- | --- |
| 首次引导 | 普通形态→微信读书选择/连接→模式选择→完成 | 合并当前完成页手势提示，不再堆解释页；已有用户不重跑 |
| 设置→桌面偏好 | 模式、普通形态、当前形态布局、名称、组件手势、常用应用 | 移除行/列间距、重复名称开关；部分选项按模式隐藏 |
| 长按应用→图标 | 默认、自选图片、透明 | 继续支持内置设置/文件入口 |
| 美化→主题 | 创建、预览、应用、导入导出外观 | 单一外观语义，不夹账号/书籍 |
| 沉浸底部最右 `»` | 全部应用抽屉，底部提供退出沉浸 | 不替换普通桌面翻页或负一屏 |
| 组件设置 | 参与切换的组件与顺序 | 桌面偏好只放方向，不重复列完整组件配置 |

## 2. 功能1：首次引导与微信读书连接

### 2.1 页面及动作

1. 选择普通桌面形态：宫格/列表；保存普通桌面选择。
2. 问“要在十雨上使用微信读书吗？”：启用/暂不启用。拒绝后直接进入普通桌面的完成步骤，不弹沉浸推荐、不清旧缓存。
3. 连接页使用单一本机录入二维码。
   - 文字说明：手机微信中打开 `weread.qq.com/r/weread-skills`，按官方提示登录并复制API Key；该地址只作文字展示。
   - 手机扫描本机二维码，进入局域网KeyEntryServer临时表单，将复制的Key粘贴到多行输入框并提交；墨水屏接收后先保存，再尝试连接验证。
   - 手机与设备需在可互通局域网；本机手输作为后备。二维码和URL均不包含API Key，临时令牌只用于本次会话。
   - 没有官方页面二维码、打开官方网页按钮或手机页面官方超链接。
4. 收到Key后用一个轻量身份相关请求验证；收到值≠验证通过。成功页提供“进入普通桌面”“进入沉浸模式”，两项同级，不默认替用户选沉浸。
5. 完成页沿用必要权限和基本手势入口：可选权限可跳过；第一次进入桌面时仅保留一条必要手势提示。

### 2.2 状态及失败语义

| 状态 | 页面反馈与后续 |
| --- | --- |
| 尚未选择 | 只在首次引导询问；升级已有completed用户不重新询问 |
| 暂不启用 | 普通桌面；以后可在微信读书设置连接 |
| 已提交、验证中 | 提交按钮禁用防重复；保留返回和稍后配置 |
| 无效/撤销Key | 显示“密钥无效，请重新获取”；不展示密钥原文 |
| 超时/断网 | 区分“暂时无法验证”；允许保留待验证值并稍后配置，不当无效Key清空 |
| 已连接、无书 | 允许进入沉浸；显示“书架暂无书籍”并保留应用 |
| 已有缓存、Key失效 | 缓存继续可见；显示连接入口，不反复弹首次引导 |

拟议 `onboarding.step` 保存断点、`onboarding.completed` 保留现语义；`wereadEnabled` 与凭据存储独立。凭据候选值/最终值只进私有凭据链路，不进通用备份/主题/日志。服务器关闭、页面退出、超时均释放监听；传输成功后清理页面输入。当前服务为局域网HTTP，产品需如实说明“同一可信网络”，不宣传端到端加密；不新增云中转。

普通用户完成连接后，后续进入沉浸直接从桌面偏好切换；不要求再次输入有效Key。原微信读书App不是数据功能前提。

## 3. 功能2：沉浸桌面

### 3.1 布局

- 顶部：小状态栏、十雨标识、时间与日期；分钟级更新。品牌标识可随最终设计再精简。
- 主体：中央在读封面、相邻书封提示、书名、章节/进度。当前本书的选书、缓存、排序和刷新直接复用，不复制数据或计时器。
- 统计：今日时长、读完书数、连续天数，一行三列；可用高度不足时先省章节，再收起统计，保留书名与进度；不缩小到不可读。
- 底部：常用应用单行＋最右固定 `»`。建议首轮默认4个常用入口＋抽屉；可在可用宽度内设2–6个，最终上限由最小点击尺寸计算。
- 标准应用触点目标至少48dp，紧凑设备若现有体系采用更小值必须专项验证；原型的像素尺寸不是Android dp验收结论。

### 3.2 行为与数据

- 常用应用单独保存入口key列表，包括内置设置/文件；不挪动普通桌面应用顺序。长按可替换/排序，不另加一个分页底栏。
- `»` 打开全屏抽屉；可用网格或列表，首版建议名称列表。返回先关闭抽屉；明确“退出沉浸模式”才恢复普通桌面。返回键不反复误切模式。
- 抽屉显示可启动应用及内置必要入口，遵守既有隐藏应用规则；管理隐藏项仍有设置入口。图标透明/名称关闭只影响桌面，抽屉始终使用可辨识图标和名称。
- 模式重启保留；切模式/旋转不重置阅读目标。刷新只使用共享book入口，返回桌面不额外建一份同步任务。
- 点击书封沿用当前已有阅读/详情能力；Key只能证明数据接口接入，不承诺获取受限书籍全文。
- 本轮推荐沉浸固定本书，普通桌面才轮换时钟/天气/微信读书等组件，避免沉浸主体被右滑变成时钟。
- 未连接用户从偏好点沉浸时提供“连接微信读书/返回”，保留原普通桌面；本地阅读沉浸另列后续，不暗中扩本轮范围。

拟议字段：`desktop.mode = NORMAL|IMMERSIVE`、`desktop.immersive.favoriteEntryKeys`、`desktop.immersive.favoriteCount`；普通 `desktop.kind` 不变。主消费者：Home布局、触摸/整理、抽屉、桌面预览、主题预览；模式不能写回普通分页配置。

## 4. 功能3：名称、透明图标与主题

### 4.1 名称与透明语义

- 合并成“显示应用名称”一个开关。迁移后的值按当前实际表达式 `appearance.showLabels && !desktop.iconOnly`，再清退iconOnly双开关；不能只取其中一个使旧用户突然显示标签。
- 单应用图标选择提供默认、自选图片、透明；透明保存为明确标记，不能伪装成不存在的PNG路径。
- 透明图标不画图像、形状底板、描边；标签由名称开关独立决定。图标透明仍占原格并可点，不等于隐藏/卸载应用。
- 透明且无名称允许存在。整理模式临时画虚线位置和名称，退出即恢复；菜单/抽屉/无障碍始终保留应用身份。固定抽屉与必要恢复入口不允许完全透明。
- 仅桌面可视呈现透明，抽屉和设置中的“默认图标”不受影响。列表模式同样不画图标；名称也关闭时，整理/抽屉负责恢复，不偷偷改用户选项。

拟议 `appearance.transparentIconTargets: Set<EntryKey>` 与现有 `iconOverrides` 互斥：选透明移除该target图片覆盖；选图片/默认移除透明标记；缓存键必须包含透明状态。内置入口使用既有IconTargets规范化规则。

### 4.2 主题包

| 包含 | 规则 |
| --- | --- |
| 图标覆盖/透明标记 | 按规范化目标身份匹配；透明标记不走跨应用补位，防止把陌生应用变成看不见 |
| 名称、字号、图标尺寸/形状 | 与实际消费者保持一致；名称使用统一字段 |
| 普通宫格/列表布局、沉浸外观 | 主题可预览并应用外观，但不自动把未连接用户切到沉浸 |
| 桌面壁纸文件 | 复制实际图片；带裁切、明暗、量化等现有显示参数；不保存外来绝对路径 |
| HOME / ALL 范围 | HOME只含首页相关图标和首页布局；壁纸是全桌面资源，两种范围都明确显示是否包含，不谎称只影响首页 |

不包含Key、阅读记录、笔记正文、隐藏应用名单、普通桌面实际全量顺序、设备方向锁、待机/关机壁纸。主题里的示例顺序仅用于匹配/预览，沿用当前“本机顺序为权威”的规则，不覆盖用户顺序。

主题新增版本字段；旧包缺少壁纸/透明字段时“不修改当前值”，显式空值才表示清除。这与配置首次升级的默认值区分。旧间距字段读入后忽略，不能重新启用已退役行为。应用前验证全部资源、尺寸及可解码性，失败不留下半套外观；导出图像预算沿用现有图片处理规则，超大壁纸先按目标尺寸处理。

## 5. 功能4与6：最少设置完成列表和分页

### 5.1 条件显示

普通宫格显示两行，明确列在前、行在后：

```text
首页应用   列 [− 4 +] × 行 [− 2 +]
其他页     列 [− 4 +] × 行 [− 5 +]
```

普通列表替换上述两行，不同时显示宫格控件：

```text
首页条数   [− 5 +]      其他页条数 [− 9 +]（窄屏拆成两行）
文字对齐   [左 | 中 | 右]
左右边距   [窄 | 标准 | 宽]
```

沉浸显示“常用应用：选择与排序/数量”，普通布局折叠在“普通桌面布局”内，切回时保留。图标尺寸/名称字号集中到“图标与文字”子页；不在首屏铺所有细节。

### 5.2 数量与空间

- 宫格首页和其他页分别存列/行；列表分别存首页/其他页条数。改变形态不互相覆盖其容量。
- 边距仅指列表左右页边留白，建议12/20/28dp三档；文字对齐作用于图标＋文字的内容组，整行点击区域不随文字缩窄。最终值按双机触点与长名称校准。
- 取消行间距/列间距手调，宫格留白由可用空间均分；列表行高由可用高度与条数推导，不提供独立间距。
- 首页先保证组件最小可读高度，再计算可容纳行数；设置显示有效值，不能“保存8行、实际只画5行”却不告知。
- 以48dp点击区域、字号、标签高度和屏幕安全区计算上限，超限加号禁用；输入法不是首选。数量不足不自动删应用，依原序分页。
- 当前 `pageLimit` 实际是最大页数（DesktopMetrics.pageCount），虽然设置文案是“每页应用上限”。新设计移除这个误导入口；不能拿它当单页容量迁移。为防应用被截掉，分页应容纳全部可见入口，不沿用会截断结果的页数限制。

### 5.3 迁移

拟议 `desktop.normalGrid.home(columns,rows)`、`other(columns,rows)`、`desktop.normalList.homeCount/otherCount/align/marginPreset`。命名待实现时冻结，不与现有数据类直接强行同名。

首次升级：旧columns分别初始化首页和其他页；旧firstPageRows初始化首页，旧rows初始化其他页。0/自动按当前设备实际布局反算并保留“自动”语义，不把0直接变1。按可读边界修正非法值，应用顺序不变。

旧行/列间距退役为不再消费；旧主题导入、普通配置加载、备份导入采用同一迁移。列表边距旧版没有独立字段，默认标准；不把旧gridAlign无证据视为用户选过列表对齐。迁移以原始字段存在性判断，执行一次且幂等。

Home几何、触摸命中、整理拖动、预览、DesktopPagination、ThemeLayout和主题HOME导出容量共用一份布局快照。新增首页独立列数后，不能继续用现有一个columns计算全部页。

## 6. 功能7：组件手势与无动画

本方案把“小组件切换”定义为**切换普通桌面参与轮换的组件**，如时钟/天气/微信读书。微信读书内部本书/本记等形态仍由“切换形态”按钮处理。这是待确认的产品口径，不混为一项手势。

桌面偏好单项：`组件切换 [右滑 | 上滑 | 关闭]`，新安装默认右滑；组件设置多选参与轮换的组件并排序。当前只有widgetId，新字段拟议 `widgetCycleIds`；升级默认仅包含原widgetId，避免无意增加用户没选过的组件。

| 起手区域/状态 | 优先处理 |
| --- | --- |
| 展开本记层 | 只给阅读层，返回/收起关闭；不透传到应用 |
| 封面带 | 左右切书，按下锁定书籍手势；不触发组件轮换 |
| 笔记正文/待办/月历可滚动区 | 组件自身滚动；到边界也不在同次手势突然切换所有权 |
| 组件标题留白/未占用背景 | 配置方向触发一次组件切换，循环到下一项 |
| 应用区/组件外留白 | 既有桌面翻页、负一屏/托盘 |
| 仅1个轮换组件或关闭 | 不切换，手势结束不误触点击 |

方向阈值复用现有swipeMinDp及明显主轴判定，不新增给用户的灵敏度滑杆；DOWN确定候选、越阈值锁定所有者、UP一次提交，CANCEL无提交。

无动画指组件、内部形态及书籍切换均直切：不做滑动预览、落位动画、渐变或自动定时轮播。数据加载使用已有内容/明确空态，不用不断旋转的加载指示。取消当前封面跟手拖动与settle连续帧属于此规则的必要影响，待实施统一调整；不把Android invalidate次数等同EPD物理刷新次数。

新组件状态保留到下次返回；切换不联网、不重建全部组件；释放不可见组件的活动计时/绘制任务。沉浸本轮固定本书，组件轮换选项在该模式下隐藏。

## 7. 本记展开失效：证据与两种方案

### 7.1 现状和原因边界

以下是本仓库源码调用链与实际依赖字节码的静态证据，并非本轮使用真实用户笔记复现：

1. `WereadBoardWidget.toggleNoteExpanded()`调用内核toggle后只requestDraw；`KernelWereadBoard.handleHit(EXPAND)`也是翻转状态并请求重绘。
2. `KernelWereadBoard.render()`的surface.frameHeight仍取Home传入的height；WereadBoardKernelSurface把同一height换成逻辑高度，没有扩高请求。
3. `DesktopMetrics.widgetRect()`永远是首页固定组件槽；HomeView.drawWidget先clipRect(rect)，随后drawPage继续绘制应用，触摸起点也只在原widgetRect内识别。
4. 实际依赖为`weread-kernel-1.3.2-k6-host1.jar`。CardRenderer.drawNoteBody包含isNoteExpanded分支，但可视正文高度仍受传入height减去抬头/按钮等限制；只改变标志无法恢复原悬浮窗由宿主改变窗口高度的能力。

因此“展开/收起按钮变了、可视内容不增加”的主因高度可信是**缺少宿主空间与绘制/命中层级联动**。不能简单删clipRect：应用仍在后面绘制、触点仍在原位置，可能盖字和误开应用。也不建议直接setFullscreen(true)，它还会改变字号、按钮和布局语义。

字节码摘要/位置见[本轮验收](../acceptance/2026-10-23-desktop-feasibility.md)，仅为本地javap证据，不声称REA反编译或原始源码。

### 7.2 推荐A：宿主内的临时阅读层，保留展开/收起

- 点击“展开”后，组件向Home提交当前笔记身份与完整可展示内容，Home在应用绘制完成后绘制一个白底阅读层。它属于本Activity，不申请系统悬浮窗权限。
- 顶边与原本记对齐；底边按当前页最末一排应用名称的实际下缘＋安全间隔计算，上限为桌面安全底边。名称隐藏时改用最后一排图标点击区域下缘。严格使用当前几何，不写死屏高百分比。
- 高度为 `min(完整正文所需高度＋抬头/操作条, 可覆盖上限)`，短文不展开无谓大白块；长文在上限内滚动/分段切页。**覆盖到名称下缘会同时挡住其上方的应用图标**，这是原需求的自然结果；展开期间应用不可点，收起恢复。
- 字号不变，只增加可视行数；若短文已全部显示，不展示无效展开按钮。
- 顶部保留书名/章节，底部固定“上一条／换一条／收起”；正文滚动不带走收起按钮。
- 触摸先给阅读层并消费全部覆盖区，禁止点击穿透；切页/打开抽屉/切组件前收起，返回键先收起再按原桌面逻辑处理。
- 临时展开状态不写主题或通用桌面配置；锁屏、离开桌面、重启、切模式后收起。数据刷新时同一笔记保留锚点；笔记被替换时回顶部。
- 旋转/字体/首页行数变化先重算当前边界，再钳制滚动位置；空间不足以容纳至少3行正文及操作条时转方案B，避免极矮展开层。
- 直切展开/收起；重绘覆盖区域与原组件区域的并集，交现有刷新策略处理。收起必须重画背后的图标/名称，避免留白残影；物理EPD专项验证另算。

技术建议：在core:widget-api现有宿主协议增加最小的阅读展开请求/关闭回调，Home掌握覆盖边界、z序与触摸；笔记数据沿现有微信读书数据契约读取，不让feature:home直接依赖feature:widgets实现或反射内核CardState。

### 7.3 替代B：打开独立笔记阅读页

按钮改“阅读全文”，打开应用内全屏白底笔记页，返回恢复桌面原状态。可复用现有笔记详情承载能力（接线前核实具体入口），长文更稳定、横屏更好适配，但不保留原地“展开”的空间连续性。

推荐A为主、B为空间不足或“阅读全文”的后备入口。不要只把“展开”改成“滚动”：这无法满足一眼看到更多文字的初衷。
