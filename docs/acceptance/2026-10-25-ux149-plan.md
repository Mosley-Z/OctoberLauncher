# UX149 只读排查与待确认方案

本轮仅交付方案及静态稿。生产代码、设备设置及安装版本未改变。用户2026-10-25最新7项要求为范围；历史方案只用于理解现状。

## 1. P4安全区与系统下拉

现状证据：`DisplaySafeArea.kt`按Eink/P4命中物理15px；竖屏左右、横屏上下避让。目标改为物理12px，S4不增加此机型补偿。壁纸、状态区、组件、应用及命中坐标须共用同一根布局范围，不能只移动画面。

`MainActivity.configureWindow`同时使用`FLAG_FULLSCREEN`和`WindowInsetsController.hide(statusBars)`；P4另外设置`BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`。P4本轮核对SDK30，确实走现代分支。两机窗口记录都有FULLSCREEN；P4多BEHAVIOR_CONTROLLED。现有自绘StatusBarView只提供点击等事件，不等于真实系统栏。未发现应用主动调用禁用系统状态栏的设备管理/锁定任务接口。

结论边界：已找到全屏策略及机型分支这一排查入口，不能仅凭这些静态字段断言ROM根因。用户反馈“P4在其他应用可下拉、桌面横竖均失败”说明不能只靠安全区解释。系统隐藏栏的边缘手势由系统处理，把应用内容内缩12px不等于把系统手势区内缩。

实施建议：先在P4统一使用现代insets策略，排除旧FULLSCREEN标志与现代控制混用及生命周期重复隐藏；以真实系统面板能否拉出为门禁。若P4固件在隐藏栏下仍不接收手势，则P4保留真实系统状态栏，并去除自绘栏重复的时间/电量显示，保留可触达的桌面刷新入口。S4不套用P4专属回退。方案不新增通知权限、无障碍依赖或自制通知面板。

验证：P4普通/沉浸×横/竖，系统面板拉出、收回、回桌面后重复；边缘与向内触摸分别验证，刷新点击不得被拖动吞掉；S4回归同矩阵。ADB技术状态不能替代盖板上的手指测试。若最终采用显示系统栏，按系统真实insets重新分配主内容高度。

官方依据：[Android沉浸模式](https://developer.android.com/develop/ui/views/layout/immersive)、[FLAG_FULLSCREEN](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_FULLSCREEN)。官方文档仅支持系统栏API/手势语义，不证明P4固件行为。

## 2. 横屏沉浸四版

设计产物：`_analysis/verify/ux149-plan/comparison.html`及`comparison/page.png`；A—D各有HTML。P4目标768×552，A另有S4 800×480适配稿`S4/page.png`。示例书名、封面、图标和统计用于比较，非实机截图；不会将示例书籍、壁纸或统计写入设备。无动效与交互实现。字体、真实封面和图标在实施时复用Android既有资源。

| 版本 | 结构 | 取舍 |
| --- | --- | --- |
| A（推荐） | 顶部时间与书名/作者/进度同行；下方左轮播、右侧三项统计竖排；最右应用列 | 最贴近用户想法；主次清楚，书籍保留较大展示面积 |
| B | 左侧时间与统计形成纵轴，右侧上方书籍信息、下方封面轮播 | 统计集中，阅读区完整；时间比A稍小 |
| C | 紧凑顶部时间/书籍信息，下方居中轮播，最下方三项统计横排 | 中轴平衡、封面居中；适合希望统计不占右侧的人 |
| D | 顶部三项统计横排，下方左时间与书籍信息、右轮播 | 大时间更醒目；封面比其他版本小 |

共同行为：进度条右侧只有一个刷新图标；保持最近10书循环和左右切换。应用列绘制与点击区域一起相对现状左移20物理px。P4物理12px与通用内容留白分别计算；应用列移位不能机械叠加成组件再缩窄20px。

长书名最多两行，作者一行；优先压缩封面空隙和轮播侧书，不缩小必要信息至不可读。S4高度不足时收紧垂直间隔和封面尺寸；不裁统计或刷新热区。图标视觉约20—24px，点击区域至少44dp，进度条与应用列不得抢同一命中区域。竖屏沿用现有结构，但补入同位置语义的刷新图标。

当前宿主ImmersiveHome单独画时间，并从书籍区域预留100dp顶部空间；书籍Painter又使用自己的百分比坐标。实施需要统一时间、书籍信息、统计和应用列几何及命中区域，不能仅移动几个文本坐标。

## 3. 连续阅读天数

已见问题：ImmersiveStatsReader从周/月缓存还原按日秒数。今天缺数据，或向前遇到缺失日期，即返回null；未尝试补取历史。界面因此可能一直显示未知。缺失缓存与明确小于60秒目前没有完整的补取闭环。只有排查和拟定修正，没有访问用户阅读正文或写入统计。

拟定口径：按设备本地日界线统计账号全部书籍合计秒数，单日≥60秒有效、<60秒中断。今天已≥60秒从今天算；今天尚未达标时从昨天算，避免每天凌晨把历史连续记录归零。例如今日30秒、昨日120秒、前日70秒、再前日59秒，则显示2天；今日达到60秒后显示3天。昨天明确<60秒则0天。

补取规则：复用现有`/readdata/detail`周期接口及baseTime，优先当前周期，再按需向前补缺失周期，直到遇到第一个明确<60秒的日期或确认账号起始边界。不能把缺失、失败或未来日期当0秒；不能用固定近7/30天截断长连续记录；当天同一秒数不得因周/月重叠而重复计入。已完成历史周期持久缓存，恢复时只补缺口；服务端未返回完整天数时保持未知或上次可信值，不伪造准确天数。

验证：59/60/61秒、今天不足阈值、昨日中断、跨月/年、周月缓存覆盖、日期缺失/补齐、网络失败、时区与跨日、长于已有缓存的连续区间。

## 4. 沉浸刷新与节能

现状：`WereadCardRefreshService`的book路径只更新书架及当前选中书进度，不等于最近10本全字段刷新；note路径会走笔记同步，不能为了10本轮播直接强制整库同步。

手动图标：一次更新书架→按最近阅读顺序确定最多10本→这些书的累计时长/进度/划线→账号今日总时长/读完书数/连续天数。复用现有账号与网关，不新增整库资产预热。重复bookId去重，空书架和少于10本正常显示；当前书仍在新候选内时保留当前书，否则回到最新一本居中。桌面本书轮播与沉浸共用候选快照，首次进入最新一本居中。

执行：后台批次共用书架/周期响应和在途请求，限制逐书请求并发；划线仅对候选书补取必要分页，复用现有更新时间与缓存证据，不能假定接口具备尚未验证的增量能力。整体状态统一通知两处轮播，避免每个字段触发一次全屏刷新。图标忙时不重复发请求，使用静态忙态而非持续旋转；失败保留可用缓存并短提示，可继续手动重试。划线数据更新到共享缓存，无需为沉浸新增正文展示区。

建议自动机制：

- 首次进入无缓存：后台取必要数据，先呈现可用缓存/未知状态。
- 唤醒、返回桌面或重新进入沉浸：距上次成功≥10分钟才进行轻量刷新（最近书单、今日/总体和变化书籍进度）；相邻触发合并。
- 从本桌面明确启动微信读书后返回：若确有停留且该书数据已过期，优先补该书与今日统计，避免强刷全部划线；不重新申请使用情况访问权限。
- 跨日且桌面可见：仅触发一次当天统计更新。历史已完成日继续用缓存，当前日不冒用昨日值。
- 滑动轮播：仅本地切换，不逐本发请求；进入后台/息屏不轮询，无常驻定时器。全量候选划线由手动刷新或已有笔记同步刷新。

“10分钟”是建议的自动轻量刷新间隔，不限制用户手动刷新。网络与界面刷新分开：时钟正常整分绘制不等于整分请求微信读书。

## 5. 删除壁纸白层

`WallpaperView.onDraw`当前可绘制alpha=0xE0的白层，非轻微亮度调整。删除该绘制和设置开关，主题导入/导出不再重新启用；旧`wallpaperWhiteOverlay/whiteOverlay`字段可兼容读取但忽略。保留壁纸原图、量化、拉伸转向及用户另设的黑色压暗参数，锁屏单独规则不从本项扩改。普通和沉浸切换不再因白层出现亮度突变。

## 6. 设备首页自动宫格

以下均为普通宫格“行×列”；其他模式保留其语义。

| 机型 | 竖屏自动 | 横屏自动 |
| --- | --- | --- |
| P4 | 1×3 | 3×2 |
| S4 | 2×3 | 3×2 |

每个方向分别保存自动/显式配置；自动只实时解析，不把推导结果写成用户手动值。用户调整竖屏不覆盖横屏，进入/退出沉浸或旋转时重新解析对应方向。自动值可在设置中显示实际解析结果；选择“自动”恢复该方向机型默认。不新增不必要设置页。

旧版本共享的非零行列视为已有显式值并保留到两个方向，不能仅因数值等于旧默认就擅自重置；零值继续自动。若历史上错误写成显式而无来源标记，无法可靠区别用户操作，保守保留，用户主动选自动后使用新默认。未知机型沿用已有默认。统一设置预览、桌面绘制/点击、排序和分页消费者。

## 7. 其他页添加组件（追加）

建议解释“套用首页配置”为：复用首页的组件清单、设置方式、外观、尺寸和有组件页布局规则；每页独立选择组件。避免在其他页换组件时连带替换首页。

- 入口：任意现有普通桌面页长按→同一组件清单；选择/关闭只作用于当前页。现有页初始不自动复制首页组件。
- 有组件页：采用首页同样的组件区/应用区规则，包括第6项设备/方向自动值和已有用户宫格设置；无组件的其他页继续现有全宽横屏3行4列、竖屏4行3列规则。
- 配置：添加时继承首页适用的组件设置作为起点，之后组件选择、图片来源及必要的页面交互状态独立；主题/字体/账号/待办数据源等全局内容共用。多个页面待办完成状态一致，同源数据刷新复用，图片滑动只改变本页图片；新增组件不能恢复已删除的组件切换手势。
- 分页：按各页实际容量累计分配应用，保留应用顺序；添加减少容量，后续应用顺延；关闭立即回填，不能留下空白。不能继续假设“首页容量+固定其他页容量”。
- 页面：组件绑定稳定页标识，应用重排不会让组件跳页；仍有组件的页面不会仅因应用清空而被删掉。组件关闭不删除应用或共用数据。
- 生命周期：只让可见页组件绘制和运行必要计时；离屏组件暂停，数据订阅复用。切换页面不得重复联网、重置阅读选择或图片索引。
- 迁移：旧首页组件原样迁移为首页配置，其他页为空；旧图片、时钟A—F、待办/本记状态保持。升级与备份恢复覆盖逐页设置。

## 实施顺序与验收边界

确认后优先P4系统栏/12px与白层、设备宫格；接着统计/刷新公共数据，再按所选布局整合沉浸；最后处理逐页组件及可变容量分页。公共契约、迁移与装配串行修改。完成源码验证后双机横竖检查，保留用户原配置并恢复临时验收状态；P4盖板手指操作单列，不以模拟滑动冒充通过。

本轮设计自查：四稿及S4稿由主代理查看，修正比较图底部裁切、封面小字和S4内容遮挡；没有独立评审。示例封面中的书名保留，不额外加说明文字到设备画面；画面仅有必要名称/数值。所有说明均在画面外。无生产构建或Android交互验收，等待用户选择和确认。
