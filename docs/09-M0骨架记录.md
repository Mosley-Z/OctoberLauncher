# M0 骨架执行记录

记录日期 2026-10-19。本阶段目标：建立可编译、可运行、可复用的工程骨架，在一台 480×800 墨水屏设备上验证设备画像与断点切换。M0 的完整定义见 [06-development-roadmap.md](06-development-roadmap.md) 第二节，本次实现范围见文末遗留项。

## 一、工程结构

```
OctoberLauncher/
  settings.gradle.kts        模块清单与仓库声明
  build.gradle.kts          插件版本登记与统一清理
  gradle/libs.versions.toml 版本目录
  gradle.properties         构建与 Android 开关
  local.properties          SDK 位置，由构建脚本按 toolchain.path 重写
  toolchain.path            共享工具链位置
  scripts/build.ps1         构建入口
  scripts/install.ps1       装机入口
  app/                      壳工程
  core/common  core/design  core/device  core/render
  feature/home
```

依赖方向 `app → feature → core`，`feature` 之间无横向引用。`core:design` 与 `core:render` 向下依赖 `core:device`，尺寸与配色集中在这两处，业务模块不出现像素字面量。

## 二、工具链复用方式

工程不复制 JDK、SDK、Gradle。`toolchain.path` 首行写 `D:\DSHStation\.toolchain`，`scripts/build.ps1` 读取后设置三个环境变量：`JAVA_HOME` 指向 `jdk\jdk17.0.20_12`，`ANDROID_HOME` 与 `ANDROID_SDK_ROOT` 指向 `android-sdk`，`GRADLE_USER_HOME` 指向 `gradle-home`，同时把 `jdk\bin` 前置到 `PATH`。脚本按 `toolchain.path` 重写 `local.properties` 的 `sdk.dir`，IDE 与命令行取同一份 SDK。

换机器或换工具链组合时只改 `toolchain.path` 一行；工具链升级时替换 `.toolchain` 内的版本目录，工程无改动。

## 四、构建与验证

powershell -ExecutionPolicy Bypass -File scripts\build.ps1

# 依赖进入共享缓存后，离线构建同样通过
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 -Offline

## 五、遗留项

后续阶段加入的内容按依赖顺序排列：

1. Hilt 与 KSP：工具链未缓存 Hilt 插件，首次引入需要网络；接入后 `app` 改为 `@HiltAndroidApp`，各模块补 `di` 目录。
2. Fragment 与 ViewModel：当前宿主为单 Activity 挂载自绘视图，M1 起改为单 Activity 加 Fragment 的导航容器，并引入 AndroidX 依赖。
3. DataStore 与 Room：配置与缓存的持久化，随 M4、M6 完成。
4. Roborazzi 截图基线与 CI：M0 剩余部分，需要网络下载 Roborazzi 与 JUnit 依赖。
5. 大屏断点验证：第二台设备 Tango 2 Pro（824×1648）本次未在线，中断点切换只验证了紧凑档，中等与扩展档待在线上机后补测。
6. 模块补齐：`core:data`、`core:network`、`core:widget-api`、`service:*` 与其余 `feature:*` 按 docs/03 的划分随里程碑加入，`settings.gradle.kts` 同步登记。
