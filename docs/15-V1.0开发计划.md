# V1.0 开发计划

编制日期 2026-10-19。本计划以 V0.9 目录快照为起点，按 0.9.x 小版本推进三个目标，三项验收完成后发布 1.0.0。所有版本全程保持可构建、可安装、单元测试通过。

## 一 版本与回溯机制

V0.9 快照已落在 `D:\DSHStation\OctoberLauncher-V0.9`，含 2893 个文件的 SHA-256 清单，版本标识 versionCode 9、versionName 0.9.0。该目录只作对照与回退，日常开发不进入。

工作副本固定在 `D:\DSHStation\OctoberLauncher`。每完成一个小版本，执行 `scripts/snapshot.ps1 -Tag 0.9.N` 生成快照到 `D:\DSHStation\_snapshots\OctoberLauncher-0.9.N`，快照内容为工作副本排除 `build`、`.gradle`、`.kotlin`、`.idea` 四类目录后的完整复制，并生成同名 `MANIFEST.sha256`。快照保留最近四份，更早的移入 `_snapshots\archive`。

版本号规则：versionCode 从 9 起每版加一，versionName 按 0.9.1、0.9.2 依次递增；三项验收全部通过后置 1.0.0、versionCode 20。`CHANGELOG.md` 记录每个版本的变更条目与对应任务编号，`VERSION` 文件记录当前版本与快照标签。

回溯规则：修改前先确认当前文件处于最新快照覆盖范围，涉及跨模块重构或删除文件的操作先补一次快照。数据迁移类改动（配置版本、数据库、缓存格式）必须提供向前迁移函数与旧版本回退函数，并在测试中覆盖双向。

## 二 三个目标的验收边界

### 目标 A 代码复核处置

高等级 8 条全部关闭：内置微信读书密钥、图片解码管线未接入、锁屏强度与冷启动锁定、启动期主线程工作、混淆与裁剪失效、release 未签名与权限过宽、更新与备份通道校验、测试与持续集成失效。

中等级 12 条关闭至少 10 条，剩余两条在 `docs/15-V1.0开发计划.md` 附表中书面记录处置结论与推迟理由。低等级 8 条与规范落差 6 项按阶段分摊，`docs/03-target-architecture.md` 与 `docs/08-engineering-conventions.md` 按实际实现重写，文档与代码二者取齐。

验收证据包括：单元测试全部通过、持续集成配置有效、ktlint 与 detekt 接入并纳入 `check`、release 产物可安装且混淆规则收窄后功能正常、`_analysis` 与 `_shots` 的密钥与产物清理完成。

### 目标 B 墨盘集成与图片能力

新建 `feature/files` 模块承载文件与图片能力，文件页保留现有 `FileLibrary` 语义，图片能力自墨盘移植。验收项包括：只读查看器（三档缩放、翻页、分享、旋转另存）、缩略图缓存（内存与磁盘两级、失效通知）、EXIF 方向归一、像素总量与堆预算保护、相册时间轴、图片编辑（范围以决策 D5 为准）、入口与负一屏文件区、图片组件与选图接入 `feature/files`、解码与抖动统一经 `core:render`。

验收证据：480×800 与 824×1648 两类设备上的像素对照截图、连续翻页 20 张的内存峰值记录、大图（4000 万像素以上）打开耗时记录、旋转另存后文件可被系统图库识别。

### 目标 C 微读墨记融合

保留十月桌面为宿主与微信读书唯一实现，微读墨记的独有能力按组件协议重绘。验收项包括：数据层新增统计、笔记、账单、排行接口与按周期分键的缓存；组件新增笔记卡、统计卡、账单卡、排行卡、阅读指纹，热力图组件增加周视图与月历数字；页面增加统计分段与全屏月历；设置页增加刷新间隔；`weread-widget\LICENSE` 的 MIT 声明在仓库与关于页保留。

验收证据：与微读墨记同屏截图逐项对照、墨色主题下的四级灰一致性检查、离线与超时降级行为记录。

## 三 团队分工与协作规则

固定角色六名，跨阶段复用，按任务领取而非按文件所有权分配。

| 角色 | 职责 | 主要写作用域 |
| --- | --- | --- |
| lead | 规划、任务拆分、方案评审、构建与快照验证、冲突裁决、最终整合 | 根脚本、`docs`、`CHANGELOG.md`、任务板 |
| dev-core | 复核第一批与第二批的 core、app、service 改动，测试与静态检查接入 | `app/`、`core/common/`、`core/data/`、`core/device/`、`service/`、`scripts/`、`.github/` |
| dev-render | 解码、抖动、缩略图、刷新管线 | `core/render/`、`feature/files` 的缓存部分 |
| dev-files | 查看器、编辑、相册、文件页入口、负一屏文件区 | `feature/files/`、`feature/content/` 的文件部分 |
| dev-weread | 微信读书数据层、组件、页面与设置 | `feature/widgets/`、`feature/content/` 的阅读部分 |
| verifier | 只读核验：构建、测试、静态检查、改动范围核对、回归冒烟 | 不写源码，仅写 `_analysis/verify/` |

协作规则：任务在共享任务板登记，写作用域互斥，同一文件同一时间只允许一名成员修改；依赖关系用阻塞标记，前置任务完成后再领取。每阶段结束由 verifier 出具核验记录，lead 复核后方可进入下一阶段。

开发期问题处理原则：可回溯的操作由执行成员按当前情况判断并记录理由；不可回溯的操作（删除目录、覆盖快照、改写配置迁移语义、清理 `_analysis` 与 `_shots`、改动签名与密钥、卸载或覆盖真机数据）一律先报告 lead，由 lead 向 Doow 申请许可后执行。

## 七 已确定的事项

D1 目标设备集合：三档全支持，480×800、552×768、824×1648。`docs/11-552x768-adaptation.md` 的档位保留，几何按三套真值表实现，`DeviceProfile` 断点相应扩展。

D2 独立 APK：墨盘停用，能力只保留在桌面内；微读墨记保留独立工程，因其仍有基于其他桌面的用户群体，融合方式是桌面侧按组件协议重绘，微读墨记源码不迁入，两侧并行演进。

D3 文件访问模型：维持 `MANAGE_EXTERNAL_STORAGE` 全文件访问，`FileLibrary` 的目录模型与墨盘 `Storage` 的语义都能直接复用。

D4 壁纸通道：改为桌面内部壁纸，不做系统 `SET_WALLPAPER`，不接厂商通道。桌面壁纸设置为桌面自绘壁纸层换图；锁屏密码界面壁纸为新增能力，源自微读墨记的对应功能并结合墨台的图片选择与量化管线升级；锁屏休眠与关机壁纸留待 1.0.0 之后开发。

D5 图片编辑范围：旋转、裁剪、五档黑白滤镜一次完成，滤镜档位与预览尺寸按三档设备实测确定。

D6 抖动范围：缩略图启用 `Ditherer` 量化，查看器默认显示灰度并在动作面板提供量化开关。

D7 release 签名：沿用 debug 签名配置，正式发布前另行替换签名与密钥。

已确定事项对阶段的影响：D1 使阶段 4.2 的几何改造按三档真值表实施，`DeviceProfile` 增加 552×768 档；D2 使阶段 8 的壁纸与负一屏任务按桌面内部能力实施，不再保留厂商通道；D4 让阶段 8.2 改为桌面壁纸与锁屏壁纸两项；D5 使阶段 5.1 的编辑范围完整；D6 使阶段 3.2 的量化范围明确；D7 使阶段 1.4 以 debug 签名验证 release 构建。
