# 开发路线与阶段计划

阶段划分以“每个阶段结束时有一个可运行的产物”为原则。工期按单人全职估算，括号内为三人并行时的参考工期。

## 一、总览

| 阶段 | 目标 | 单人 | 三人并行 | 完成标志 |
| --- | --- | --- | --- | --- |
| M0 骨架 | 可编译、可运行、CI 就绪 | 1.5 周 | 0.5 周 | 全新包名的空壳桌面能在 480×800 与一台大屏机型上启动 |
| M1 桌面 | 应用区、手势、翻页、整理 | 3 周 | 1.5 周 | 可作为日常桌面使用，图标点击与分页正常 |
| M2 组件 | 组件协议与十三个内置组件 | 2.5 周 | 1.5 周 | 组件库可选可换，刷新策略生效 |
| M3 托盘 | 状态栏、快捷托盘、媒体 | 2 周 | 1 周 | 亮度、前光、WiFi、蓝牙、通知全部可用 |
| M4 设置与主题 | 数据驱动设置与主题模型 | 2 周 | 1 周 | 全部配置项可改可存，主题包可导入导出 |
| M5 系统能力 | 通知监听、悬浮层、前光、更新 | 3 周 | 1.5 周 | 托盘悬浮层与悬浮状态栏在真机可用，更新流程自建 |
| M6 内容域 | 书架、文件、微信读书、KOReader | 3.5 周 | 2 周 | 三个内容面板与文件管理全部可用 |
| M7 适配打磨 | 断点调参、机型实测、性能、文案 | 3 周 | 1.5 周 | 覆盖十二款机型的三档断点 |
| M8 发布 | 签名、混淆、体积、隐私、服务器 | 1.5 周 | 0.5 周 | 可分发安装包与更新清单上线 |

单人累计约 22 周，三人并行约 11 周。M2 与 M3、M6 可并行，M5 依赖 M3 的托盘宿主。

## 二、M0 骨架

建立 `app` 与十一子模块的 Gradle 骨架、版本目录、Hilt 接入、日志与诊断、主题资源与尺寸令牌、`DeviceProfile` 与三档断点、`InkCanvas` 与 `BitmapPipe` 的最小版本、Roborazzi 截图基线、CI 脚本。

关键的验证动作：在一台 480×800 墨水屏机型与一台 1080×2400 液晶机型上各截一张图，确认布局按断点切换，无写死像素导致的溢出。上游的屏幕门禁在这里换成能力判定，任何分辨率都能进入桌面。

## 三、M1 桌面

实现应用枚举（`QUERY_ALL_PACKAGES` 与 `RoleManager` 的 HOME 接管）、图标加载与缓存、宫格与列表两种形态、按断点计算的列数与行数、`ViewPager2` 翻页、`GestureController` 的两阶段长按与滑动、按压反色、整理模式、隐藏应用、排序、图标包选择入口。

与上游的差异：宫格列数由单元格最小宽度计算（上游固定 3 列），首屏与其余页的行数也不写死，页数上限由配置决定（上游 15 页）。

验证：冷启动进入桌面 800ms 以内，滚动 50 个应用无掉帧（液晶）与无残影（墨水屏），长按整理与拖拽在两种形态下都可用。

## 四、M2 组件

先写 `core:widget-api` 与 `WidgetHost`，再按依赖顺序实现十三个组件：阅读进度、天气、大时钟、紧凑钟面、月历、本地封面流、微信读书书架、微信读书月度、微信读书摘录、KOReader 月热力、使用统计、自定义图片、占位，对应上游 `data\DeskWidget.java:29-41` 的十三个 ordinal；便签与媒体控制作为上游没有的新增组件，同时充当扩展验证用例。

每个组件模块含三部分：`Provider` 实现、状态来源（Repository 或 Flow）、预览数据。组件库页面由 `WidgetRegistry` 自动生成，分类来自协议字段。

验证：新增一个组件不修改 `home` 模块的任何文件（用便签组件作为验证用例）。

## 五、M3 托盘

`feature:tray` 实现状态栏与托盘两块界面，`TrayTile` 协议注册各区块。先做 WiFi、蓝牙、前光、亮度、通知，再做悬浮层开关与媒体控制。

托盘数据源：WiFi 与蓝牙用 `WifiManager` 与 `BluetoothManager` 的广播或回调，前光经 `Capability` 探测厂商通道，通知经 `service:tray` 的 Flow。

验证：托盘在 480×800 与大屏上都完整可见，控件不重叠；亮度与色温十档写入生效；媒体控制在三款播放器上可用。

## 六、M4 设置与主题

`SettingsSpec` 与 `ConfigRepository` 先行，再做五组设置页：桌面、外观、托盘、锁屏、集成。主题模型包含配色、圆角、线宽、字体、图标映射、壁纸与色调，序列化为 `theme.json` 打包成自有扩展名。图标包支持打包扫描与运行时选择，字体支持从 `Fonts` 目录导入并预览。

验证：修改任一配置后杀进程重启仍生效；主题包导入导出往返一致；配置 schema 版本从 1 演进到 2 的迁移脚本有单测覆盖。

## 七、M5 系统能力

`service:tray` 与 `service:overlay` 两个模块。通知监听改为订阅式并新增过滤配置；无障碍服务提供悬浮层、按键注入、整屏刷新；前光优先厂商提供者探测与系统设置回退；更新使用自建清单（版本、渠道、下载地址、SHA-256、签名指纹），支持差量与全量。

验证：通知在投递后 200ms 内出现在托盘；下拉悬浮层在任意应用之上可用；更新包签名不符时拒绝安装。

## 八、M6 内容域

书架与合集（Room 存储，JSON 导入导出）、文件管理（浏览、复制、移动、重命名、删除、解压、缩略图）、微信读书接入（密钥配置、书架、进度、月读统计）、KOReader 接入（目录扫描、书架、阅读统计）、天气（自建或第三方数据源，多源适配）。

验证：合集在应用重启与备份恢复后完整；KOReader 统计库只读拷贝后查询不锁库；微信读书密钥错误时给出明确提示。

## 九、M7 适配打磨

三档断点逐机型调参，重点是大屏与折叠屏的分栏、平板上的列数与字号、墨水屏的刷新策略与残影控制。文案国际化到中文与英文，日期与数字格式随区域。可访问性：焦点顺序、内容描述、字号缩放。

验证：十二款机型清单（见 [05-device-adaptation.md](05-device-adaptation.md)）逐台执行一遍主流程截图；`TalkBack` 下可完成打开应用与切换组件。

## 十、M8 发布

签名与从 0 开始的发布证书、R8 全量混淆与资源压缩、APK 体积控制到 8MB 以内、隐私声明与权限说明、更新服务器与清单托管、商店素材与截图。

验证：`apkanalyzer` 检查无上游包名、类名、字符串与域名残留；`aapt2 dump badging` 确认包名与权限集；DEX 字符串搜索 `tomo`、`astraabove`、`weread` 密钥模板均无命中。

## 十一、关键决策点

| 决策 | 选项 | 建议 | 验证方式 |
| --- | --- | --- | --- |
| UI 体系 | View 或 Compose | View | 在 480×800 墨水屏上做同一页面的两版实现，比较刷新次数与滚动残影 |
| 组件加载 | 编译期注册或动态插件 | 编译期注册 | 动态加载需 `AssetManager` 与类加载隔离，插件签名与版本兼容成本高，先用编译期注册 |
| 配置存储 | DataStore 单键 JSON 或按字段存 | 单键 JSON | 配置项约四十个，单键序列化读写一次完成，迁移只需版本号 |
| 通知监听 | 订阅式或轮询 | 订阅式 | 订阅式可实时更新托盘，轮询在上游造成数据滞后 |
| 更新通道 | 自建或应用商店 | 自建加商店并行 | 墨水屏机型多不在主流商店，自建通道覆盖全部机型 |
| 主题扩展 | 仅壁纸与图标或完整主题模型 | 完整主题模型 | 上游主题包只承载壁纸、色调与图标，完整模型可覆盖配色与令牌，需在 M4 前定字段 |

## 十二、验收基线

功能对等：`01-feature-inventory.md` 的十二个功能域逐条勾选，缺失项必须写明理由。上游缺失的媒体控制、定时全刷、多语言在 M2 与 M7 补齐。

身份隔离：产物中无上游包名、类名、资源名、字符串、域名、UA、签名；与上游的构建产物对比无共享类与资源。

可扩展：新增组件不触碰宿主；新增设置项只加节点声明；新增数据源只实现接口。

可适配：三档断点各覆盖至少一款机型，无写死像素，横竖屏与折叠态均不错位。

可维护：模块间无循环依赖，单模块测试覆盖率 60% 以上，CI 全绿，冷启动与内存达标。
